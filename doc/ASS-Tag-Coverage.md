# ASS/SSA 覆盖标签与绘图能力完整清单

**回答的问题**：一个生成器要做到"完全等价于所有 ASS 能力"，必须能发出哪些标签。

**证据等级标注**（全文遵守，不混用）：

| 标记 | 含义 |
|---|---|
| **[源]** | 上游源码逐行确认（libass `ass_parse.c` / Aegisub `kara-templater.lua` / VSFilterMod `RTS.cpp`） |
| **[测]** | 本机渲染 + 像素级实测（ffmpeg n9.0.2 → libass；HXLoLi 定制 WASM） |
| **[官]** | 官方文档原文 |
| **[未找到]** | 在权威来源中确实不存在，或无法确证 |

本机两个渲染器的实测身份：

- **系统 libass**：ffmpeg n9.0.2 内置（`libass/ass_parse.c` 全量枚举 **53** 个认可的标签名）
- **定制版**：`assets/octopus/libass/libass.wasm`（SubtitlesOctopus 分叉，tarball 0.17.3，含 `[vsfiltermod] Failed to load/decode image` 等上游没有的字符串）

---

## 0. 结论摘要（先看这个）

一个"完全等价"的生成器必须能发出 **53 个标准标签** + **17 类 VSFilterMod 扩展**。但真正的风险不在"能不能发出"，而在**发出去了却没有效果**。实测拿到 **12 条静默失效路径**，其中 4 条是「标签前缀互相劫持」，会让整条标签被吃掉或改写语义  这类错误既不报错、也不改变输出到可疑程度，是最难在审查中发现的。

---

## 1. 标准 ASS 标签全清单

全部 53 个标签名由 **[源]** `libass/libass/ass_parse.c` 逐行枚举（`tag("...")` / `complex_tag("...")`），参数语义由 **[官]** Aegisub *ASS Override Tags* + **[测]** 交叉验证。

### 1.1 定位

| 标签 | 参数格式与单位 | 可动画（放进 `\t`） | 内联覆盖 | 关键实测约束 |
|---|---|---|---|---|
| `\pos` | `\pos(<x>,<y>)` x,y = 脚本分辨率像素 | **否** [源]无 pwr | 是 | 一行只能有一个；与 `\move` 互斥，**先出现者胜** [源][测] |
| `\move` | `\move(<x1>,<y1>,<x2>,<y2>[,<t1>,<t2>])` 像素 + 毫秒（相对行起点） | **否**（自身即动画） | 是 | 参数个数必须 **4 或 6**；其它 → 整段丢弃 [源]。一行只能一个 [官] |
| `\org` | `\org(<x>,<y>)` 像素 | **否**；放进 `\t` 实测无变化 [测] | 是 | 一行只认第一个 [源]；不能动画 [官] |
| `\an` | `\an<1..9>` 小键盘布局（1=左下 … 9=右上） | **否** [源] | 是 | — |
| `\a` | `\a<1..11>` SSA 遗留码（1/2/3 水平，+4 顶，+8 中） | **否** [源] | 是 | 每行只认第一个；非法 `\a8`/`\a4` 被当 `\a5` [源] |

### 1.5 时间

| 标签 | 参数格式与单位 | 可动画 | 内联覆盖 | 关键实测约束 |
|---|---|---|---|---|
| `\t` | `\t(<t1>,<t2>[,<accel>,]<tags>)` 毫秒（相对行起点） | 自身即动画 | 是 | 参数档位 `cnt=1/2/3/其它` 语义不同 [源]：`cnt==3` → `(t1,t2,accel)`；`cnt==2` → `(t1,t2)`；`cnt==1` → 该参当 **accel**；`cnt==0` → 全行 |
| `\t` accel | 1 = 线性；`<1` 快→慢；`>1` 慢→快 | — | — | 数学形式 `y = x^accel`，`x=(t-t1)/(t2-t1)` [官] |
| `\fad` | `\fad(<t1>,<t2>)` 毫秒，淡入/淡出时长 | **否** | 是 | 等价 `\fade(255,0,255,...)` [源] |
| `\fade` | `\fade(<a1>,<a2>,<a3>,<t1>,<t2>,<t3>,<t4>)` alpha 0–255 + 毫秒 | **否** | 是 | **参数个数必须 2 或 7**；其它 → 整段忽略 [源][测] |
| `\k` / `\K` | `\k<厘秒>` | **否** | 是 | `\K` == `\kf` [源] |
| `\kf` | `\kf<厘秒>` 平滑扫过 | **否**（受限，实测不可靠） | 是 | 厘秒 → `×10` 转毫秒 [源] |
| `\ko` | `\ko<厘秒>` 仅描边填充 | **否** | 是 | — |
| `\kt` | `\kt<厘秒>` 强制重置卡拉OK计时 | **否**（`\t` 内实测无变化 [测]） | 是 | 厘秒 → `×10`；**负值 = 延后启动** [源] |

实测说明：单条 `{\k100}ABCD` 在所有帧都不产生任何像素  因为 `\k` 的 Primary/Secondary 只在**有可见差异时才显现**，且 libass 在事件范围内按 `effect_timing` 分配。要看到卡拉OK 效果必须给 SecondaryColour 一个与 Primary 不同的值 **[测]**。

### 2.2 标签清单（三源交叉：[官 wiki] + [源 `RTS.cpp`] + [博 中文说明]）

### 2.3 本机定制版实测结果（决定性）

对同一份文本/图形，逐像素 diff：

| 标签 | 定制版 WASM | 证据 |
|---|---|---|
| `\fsc` | **真实生效** | `\fsc50` → 宽 76（0.5×）；`\fsc100` → 150（1.0×）；`\fsc300` → 448；`\fsc0` → **空**（缩放到 0）。对照 `\fscx300\fscy300` → 448×128，确认是"聚合缩放"语义 |
| `\fsvp` | **真实生效** | `\fsvp100` 在 `\pos(100,600)` 下把文字推到 y=707（+107px） |
| `\1img` | **真实生效** | `\1img(dot.png)\p1` 绘出纹理，主色 = 图片色 `(255,40,40)`；报错串 `[vsfiltermod] Failed to load/decode image` / `Image too large` 是上游 libass 没有的 |
| `\distort` / `\rnd*` / `\rnds` / `\frs` / `\jitter` / `\1vc` / `\$vc` / `\1va` / `\$va` | **实测不生效**（逐像素与基线相同） | 12 组对照全部 `差异=无(像素相同)`，含加了边框、避开 `\pos` 冲突的复测 |
| `\moves3` / `\moves4` / `\mover` | **实测不生效** | 时间序列 t=0.1/1.0/2.0/3.0/3.9 位置恒定；`\move` 对照正常位移 |
| `\movevc` | **实测不生效** | 含与不含 `\movevc` 的帧像素相同 |

**证据边界（重要）**：定制版 WASM 的字符串表**同时存在** `distort` `rndx` `rndy` `rndz` `frs` `fsvp` `1img`~`4img`，但只有后四类真正生效。`rndx` 的相邻字符串是 `fscx`、`rndz` 的相邻是 `frz`  说明这些名字确实在同一张与标签相关的表里。字符串存在**不等于**功能可达；上表是渲染结果的判定，不是字符串的判定。本机这份 WASM 的行为就是这样，不能推广到别的 VSFilterMod 分叉。

## 3. libass 与 SubtitlesOctopus

### 3.1 三者关系（关键结论）

```
VSFilterMod (Gabest, 已死)          libass (活跃上游, 0.17.5)
        │                                   │
        └── 私有标签扩展，从未并入 ──────────┘  ✗ 无血缘
                                            │
                        JavascriptSubtitlesOctopus = libass 的 emscripten 构建 + JS 封装
                                            │   （.gitmodules: lib/libass → github.com/libass/libass.git）
                                            │
                                    不是 fork，是构建产物
```

**结论**：SubtitlesOctopus **不是** VSFilterMod 的 fork，它编译的是**上游 libass**。所以：

- 官方 Octopus **默认不支持任何 VSFilterMod 扩展标签** [官 README: "Supports most SSA/ASS features (everything libass supports)"]
- 你在网页播放器里看到 `\1img` 生效，说明那个站点**用了自己改过的 libass 构建**（本机这份就是），不是 Octopus 的能力
- 「是 fork 还是独立实现」的答案是第三种：**Octopus 是 libass 的 WASM 打包层；VSFilterMod 支持与否取决于打包的是哪份 libass**

### 3.2 libass 对扩展标签的支持

| 类别 | libass 行为 |
|---|---|
| libass 原生支持 | §1 全部 53 个标准标签（由 `ass_parse.c` 逐行枚举，非文档列举） |
| VSFilterMod 风格标签 | **有意不支持**。libass 有一个可选开关 `ASS_FEATURE_INCOMPATIBLE_EXTENSIONS`（`ass.h:241`）用于启用与 VSFilter 不兼容的扩展；VSFilterMod 那批标签不在此列。**本机这份 WASM 的字符串表里查不到 `incompatible`/`extension` 字样**，说明它的 VSFM 支持是私有补丁，不是靠这个开关 |
| 未知标签 | **静默忽略**：`ass_parse_tags` 的 `else if` 链走完后没有 `else` 分支，无任何告警 [源]。规范层面 `{}` 内无法识别的文本本来就被当作注释 [官] |

### 3.3 SubtitlesOctopus 支持的标签

| 项 | 值 |
|---|---|
| 支持的标签集 | **等于所链接 libass 的支持集**。用上游 libass → 仅 §1 的 53 个 |
| 自带 render mode | `js-blend` / `wasm-blend` / `lossy`（实验性，README 标注"不稳定、部分浏览器不可用"） |
| 性能相关开关 | `prescaleFactor`、`prescaleHeightLimit`、`maxRenderHeight`、`libassMemoryLimit`、`libassGlyphLimit` |
| `dropAllAnimations` | 为 true 时**尝试丢弃所有动画标签**；README 明确警告会严重破坏复杂字幕，且对"手工编辑或分配过的事件"不可靠  **这是批量生成后出现"特效消失"的一个真实陷阱** |
| 版本 | 仓库无 Changelog（404）；本机这份 wasm 内嵌 tarball 标记 `0.17.3` |

## 4. 静默失效清单

**全部条目都有本机可复现的实测证据**（标准 libass = ffmpeg n9.0.2；定制版 = 本机 WASM）。这是本文最有价值的部分。

### 4.1 前缀劫持（最隐蔽  一条标签被另一条吃掉或改义）

| # | 写法 | 实际发生什么 | 为什么 |
|---|---|---|---|
| 1 | `\moves3(x1,y1,x2,y2,x3,y3)`（**6 参**） | 变成**直线移动**：从 (x1,y1) 到 (x2,y2)，时间窗取 **x3,y3**（当作 t1,t2，且 `t1>t2` 时自动交换）。**逐帧铁证**：`\moves3(100,100,500,100,900,500)` 的 4 帧位置 `[(101,111),(501,111),(501,111),(501,111)]` 与 `\move(100,100,500,100,500,900)` **逐帧像素完全相同（4/4）**，而与 `\move(...,0,4000)` 不同  证明 900 被当 t1、500 被当 t2、900>500 触发交换 | `move` 分支在 `moves3` 之前；`move` 守卫 `nargs==4 \|\| nargs==6`，6 参的 moves3 正好命中 [源][测] |
| 1b | `\moves3(...,<t1>,<t2>)`（**8 参**） | **整段丢弃**（实测末帧仍在 `\an7` 原位 (11,18)，且全帧恒定） | 8 参不满足 `nargs==4\|\|6` → `continue` [源][测] |
| 2 | `\moves4(...8 参)` | **整段丢弃**，无效果 | 同 1b [源][测] |
| 3 | `\mover(...8 参)` | **整段丢弃**（`\mover` 的 4/8 参版本都不可达） | 同 1b [源][测] |
| 4 | `\movevc(x1,y1,x2,y2)` | 变成 **`\move` 语义的水平位移**（实测 x 从 81 变 11，即位移 −70 = x1−x2 方向） | `movevc` 被 `move` 吃掉，6 参 → 合法 `\move` [源][测] |

> 第 1 条的实践含义：素材里凡写成 6 参 `\moves3` 的"贝塞尔运动"，**从未按贝塞尔跑过**，而是一直在按直线 + 一个荒谬的时间窗跑（若 `y3 > x3` 则时间窗被交换成 `x3→y3` 毫秒）。这类"看起来在动、但动法不对"的错误最难在人工审查中发现。
| 5 | `\fsvp<数>` | **变成 `\fs`** → 字号**被重置回样式值**，且**顺序无关**：`\fs100\fsvp60` 与 `\fsvp60\fs100` 都得到样式字号（216），即 `\fsvp60` 出现后字号恒定回样式；`\fsvp60` 单独出现也等于 `\fs` 无参（216）。对照：`\fs50` 宽 168、`\fs100` 宽 336，可看出 `\fsvp` **从不**产生 `\fs` 之外的任何效果 | `fs` 排在 `fsvp` 前；`fs` 对 `vp60` 无从解析数字 → `nargs=0` → 回样式 [源][测] |
| 6 | `\frs<角度>` | **变成 `\fr`** → 旋转被重置为样式 `Angle`。实测 `\frz45\frs30` == 基线（无旋转） | `fr`（= `frz`）排在 `frs` 前 [源][测] |
| 7 | `\rnd<数值>` / `\rnds<数值>` | **变成 `\r`** → 样式被整体重置（颜色一起丢）。实测 `\1c&HFF0000&\rnd40` 主色 = 白色，且**与 `\1c&HFF0000&\r` 逐像素相同** | `r` 排在 `rnd*` 前 [源][测] |
| 8 | `\blip<任何内容>` | **被 `\b` 吃掉且被解释成 `\b0`** → 强制取消加粗。**逐像素证明**：`\b1` 宽 241、`\blip1` 宽 216、`\b0` 宽 216，且 **`\blip1` 与 `\b0` 像素完全相同**；在 Bold=TRUE 的样式下 `\blip1` 同样强制变窄（241→216）。成因：`\b` 的守卫要求参数为 0/1/≥100，`blipXY` 解析出的参数非法 → 回退到 `state->style->Bold`，在样式 Bold 为假的常见情况下就等价于 `\b0` |
| 9 | `\rndx` / `\rndy` / `\rndz` | **整段丢弃** | 不被 `\r` 吃（`r` 之后是 `n` 不是空/样式名），也无匹配分支 → `continue` |
| 10 | `\fsc<百分比>`（标准 libass） | 参数**被丢弃**，只留下"重置为样式 ScaleX/Y"。实测 `\fsc180` == 基线；`\fscx50\fsc` 回到 100% | `fsc` 分支无视 `nargs` [源][测] |

> 判定规则（**[源]** 直接读出来的）：libass 用 `mystrcmp(&p, "name")` **逐字符前缀比较**，匹配即认为命中。所以**任何比标准标签更长的标签名，只要前 1–4 个字符撞上标准标签，就永远到不了自己的分支**（除非该标准标签的守卫会 `continue` 放行）。
>
> 生成器必须知道的推论：`\fsvp`、`\frs`、`\rnd*`、`\blip`、`\moves3/4`、`\mover`、`\movevc` 这七类名字**在标准 libass 上没有一个能按本意工作**。

### 4.2 `\t` 参数解析

| # | 写法 | 实际发生什么 |
|---|---|---|
| 11 | `\t(0,2000\fscx300)`  **漏了 accel 的逗号** | 不报错，但**整条 `\t` 退化成全程恒定终值**：实测 t=0 与 t=1 及末帧的 bbox 都是 495×151（即 300% 的大小），完全没有动画过程。原因：`cnt==1` 时那个参数被当成 **accel**（值为 0），而 `y=x^0` 恒为 1 → 从第一帧就是终态 [源][测] |
| 12 | `\t(0,2000,)` 空 tag | 无效果（`has_backslash_arg` 为假 → `continue`） |
| 13 | `\t` 内放**矢量** `\clip` | **不生效**。实测矢量 clip + `\t` 逐帧像素完全相同；矩形 clip + `\t` 则正常推进 [官][测] |
| 14 | `\t` 内放 `\pos` / `\org` / `\an` / `\pbo` / `\p` / `\fe` / `\kt` | **不生效**（`\pos` 因 `EVENT_POSITIONED` 已置位被忽略；`\org` 因 `have_origin`；其余分支无 pwr）[源][测] |
| 15 | `\t` 嵌套（`\t(0,2000,\t(0,1000,\fscx300))`） | **行为异常**：实测内层把缩放推到 300% 后**不再回落**，与"内层 0–1000ms、外层 0–2000ms"的直觉不符。0.15.0 起改为"像 VSFilter 一样对待非法嵌套 `\t`" [源] |
| 16 | 同标签多条 `\t` 叠加 | 结果取决于**出现顺序**，实测两种顺序给出不同曲线  官方明说这是"不可依赖"的 [官] |

| `line` | 正在产出的行（**唯一可写**的） |
| `orgline` | 产生当前音节的原行 |
| `syl` | 当前音节；`char`/`multi` 下是改了若干值的伪音节 |
| `basesyl` | 原音节；`syl == basesyl` 说明当前既非 `char` 也非 `multi` |
| `meta` | 脚本元数据（`meta.res_x` / `meta.res_y` = 脚本分辨率） |
| `tenv` | 代码环境自身（`tenv.tenv == tenv`） |
| `_G` | 主环境，可取 Lua 标准库 |

预加载模块：`karaskel`、`unicode`、`utils`（通过 `_G` 访问）。

## 附：对生成器的三条硬要求

1. **发出前做前缀冲突检查**。任何扩展标签名，先看它的前缀是否命中标准标签（§4.1 的 10 条）。命中的一律不许发到标准引擎上。
2. **`\t` 内只允许"有 pwr 的分支"**。安全集 = `\bord \xbord \ybord \shad \xshad \yshad \fax \fay \blur \be \frx \fry \frz \fscx \fscy \fsp \fs \1c..\4c \1a..\4a \alpha \clip(矩形) \iclip(矩形)`。其余放进去等于没写。
3. **验收必须在目标引擎上做**。§2.3 已证明同一份 ASS 在两个引擎上会得到截然不同的结果；用 ffmpeg 测扩展标签会得到"静默退化成填充色"的假结论。
