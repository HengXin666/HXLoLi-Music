# 歌词语义 → 视觉参数 的映射模型

**这份文档是本项目自己的东西**，不是从任何成品或论文抄来的参数表。
它是从三处**已验证的事实**推出来的一个可执行模型：

1. **Kinetic Typography Diffusion Model**（ECCV 2024, arXiv 2407.10476）证明了
   「外观」与「运动」应当作为**两组独立条件**分别控制，而不是混成一个"风格"。
   它的数据集是 584 个专业动效师的模板。
2. **Valence × Arousal 二维情感模型**是情感计算领域的标准表示
   （心理学维度模型，见 Wikipedia *Emotion classification* 的 Dimensional models 一节）。
3. **WCAG 2.1 的对比度判据**给出了可读性的硬下限（本项目 `KFX-RULES.md` 已固化）。

**arXiv 上「歌词→视觉参数」的直接研究是空白**  搜 `kinetic typography` 只得到那两篇，
搜 `emotion + motion + design` 得到的是机器人动作与微表情，没有一篇做歌词。
所以这份模型是**从上面三条推导**出来的，不是复述。

---

## 一、拆成两个正交轴

关键决策：**语义不直接映射到颜色，而是先映射到「情感坐标」，再由坐标生成参数。**
中间多一层，是因为情感坐标可以**跨作品复用**，而颜色不能
（Charlotte 的四色是 Charlotte 的，东方该有东方的一套）。

```
歌词语义 ──① 语义打分──▶ (valence, arousal, 意象) ──② 参数生成──▶ 视觉参数
                                                              ├─ 颜色（外观轴）
                                                              └─ 运动（动态轴）
```

**为什么分两轴**：论文那篇的实证是外观与运动必须独立引导。
一件成品"看起来像什么"和"怎么动"是两个决策；混在一起就会得到
"所有悲伤的歌都用蓝色缓动"这种模板化结果  这正是本项目的失败模式。

## ② 参数生成：由坐标推导（这部分是可执行的）

### 颜色轴：由 valence 定色相区，由 arousal 定饱和/明度

| 轴 | 取值 → 效果 |
|---|---|
| **valence**（负→正） | 色相：负值偏 200°–280°（深蓝/紫）→ 中性 40°–60°（土黄/铜）→ 正值偏 90°–160°（青绿/黄绿） |
| **arousal**（低→高） | 饱和度与描边粗细：低唤醒→低饱和、细描边（`\bord2`）；高唤醒→高饱和、粗描边（`\bord5`） |

**填色恒定纯白 `#FFFFFF`**  这不是偷懒，是 `KFX-RULES.md` 那条
"描边必须比中灰更暗"推出来的：填色越亮，描边可用的色域越宽。
把色彩表达全部交给描边，可以同时拿到可读性与表现力。

### 运动轴：由 arousal 定时长，由 valence 定曲线方向

| 轴 | 取值 → 效果 |
|---|---|
| **arousal**（低→高） | 动作时长：低唤醒 400–600ms（缓、舒展）→ 高唤醒 120–200ms（短促、急促） |
| **valence**（负→正） | 缓动方向：负值用 `ease-in`（先慢后快，像下沉）；正值用 `ease-out`（先快后慢，像浮起） |

**ASS 的可达范围**（实测约束，不是猜测）：ASS 的 `\t(...,accel)` 是幂函数 `y = x^accel`，
只能覆盖幂族缓动。**所以运动轴只承诺能做到的**：
`ease-out` 用 accel < 1，`ease-in` 用 accel > 1，想做过冲就拼两段 `\t`。
不承诺 spring / 贝塞尔  那是格式天花板，靠拼接近似。

## ③ 意象：剩下的自由度

颜色与运动被两个坐标占满之后，**"这句在说什么"还剩一块没被用掉**
具体名词、动词、场景。这才是把"悲伤的歌"和"这首歌"区分开的东西。

意象不走情感坐标，走**语义匹配**：歌词语义 → 母题库里的图形。
判定优先级（从高到低）：

1. **作品专有符号**（东方 = 御币/鸟居/风车；缘之空 = 向日葵/蝉/天空）
2. **句子里的具体名词/动词**（"風" → 风的轨迹线；"涙" → 水滴）
3. **段落情绪兜底**（都没命中时用通用光点，但降低密度）

**为什么意象优先级最高**：它是唯一"别人抄不走"的层。
颜色和运动都是参数，任何歌都能套；只有意象绑定到具体作品。

## 三、这套模型的可证伪之处

一个模型必须能被证伪，否则是玄学。以下是能被实测推翻的断言：

| 断言 | 怎么验 |
|---|---|
| 填色纯白 + 彩色描边 比 同色系深浅 更清晰 | 跑 `check_contrast.py` 比对比度 |
| 高唤醒句子的动作时长应短于低唤醒 | 统计成品里 `\t` 区间中位数与 arousal 的相关性 |
| 意象层是区分度的来源 | 把意象层去掉，成品会退化成"任何歌都能套" |
| 两轴独立优于单轴 | 实测：只调颜色不动运动 vs 两轴联动的观感差异 |

**第三条是可以直接做的对照实验**：同一组参数，加/不加意象，看能否分辨是哪首歌。

## 四、与既有做法的差别（为什么这是新的）

| 做法 | 它怎么决定视觉 | 缺什么 |
|---|---|---|
| 公开模板集（481 例等） | 人工挑一个喜欢的 | 与歌词无关 |
| Charlotte 等成品逆向 | 抄它的配色与节奏 | 抄完还是它的，不是这首歌的 |
| ALGOGEN 式的 IR | 解决"AI 输出太长"，不解决"输出什么" | 只谈格式，不谈语义 |
| **本模型** | 语义 → 情感坐标 → 参数 + 意象匹配 | 待实测验证 |

前三者在**格式层**解决问题（怎么写 ASS、怎么压缩），本模型在**决策层**解决问题（写什么）。
