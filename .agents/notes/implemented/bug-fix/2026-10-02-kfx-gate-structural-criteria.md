# Agent Note: KFX 红线改用结构化判据（注音层 / 特效贴合 / 配色稳态）

Status: implemented

- 影响: `py/ass/quality_gate.py`、`py/music/kfx_gate.py`（内嵌副本）
- 相关: [kfx-quality-redline](../process/2026-09-28-kfx-quality-redline.md)（本篇修正它的三条判据）、
  [kfx-readability-gate](../process/2026-09-27-kfx-readability-gate.md)（对比度门槛本身不变）

## Problem

用户交付两份新成品（無職転生 ED1「オンリー」、ヨスガノソラ OP「比翼の羽根」）要求替换进播放列表，
两份都被红线拦下。用户直接指出：**「我感觉是他这个脚本的门禁有问题，而不是 ASS 有问题」**。
逐条复算后，三条判据各自错在不同的地方。

**1. 注音层写死了样式名 `-furigana`**

```python
out["has_furi_style"] = any("-furigana" in s for s in d["styles"])
```

但本仓自己的模板 `.agents/skills/hx-anime-karaoke-ass/templates/make_ass_template.py:41`
生成的是 `doc.add_style("RB", "Shippori Mincho B1", 34, bold=1)` —— **判据与自家模板互相矛盾**。
用户两份新成品同样用 `RB`，于是 8232 / 9733 / 9156 条事件被判「样式无 / 事件0」。
同一类命名还有 `FURI`（ヨスガ ED 的 117 条注音）。

实测全库样式名：`RB` / `FURI` / `-furigana` / `Default-furigana` / `OPJP-furigana`……
命名毫无规律，而**语义特征跨作品稳定**。

**2. 特效贴合度拿「全文件文字 y 中位数」当 band**

```python
ty = sorted(t_y)[len(t_y)//2]          # 一个标量
far = sum(1 for (_x, y) in path_boxes if abs(y - ty) > slack)
```

失败在于把**多带结构压成一个标量**。同一个文件里同时存在标题卡、注音、日文、中文多行
（无职 ED 实测 875/915/982 三行，标题卡锚在 353），单一中位数既代表不了"带"，
还会让标题卡的装饰去跟歌词行比。

**权威答案是现成的**：这两份（以及本 skill 生成的全部）成品在文件头写下了每句的 band，
并在事件的 `Name` 字段声明归属 —— skill 硬规则第 5 条强制要求：

```
; assfx-band: p00 563.9 812.0 1356.1 1054.0 25.15 29.16
Dialogue: 0,0:00:25.88,0:00:28.18,FX,fx:p00,0,0,0,,{...}
```

按它**自己声明的 band** 复算：无职 ED 1780/1780 在带内、ヨスガ OP 1077/1077 在带内 ——
**0 条越界**。而旧判据报 20.2% / 42.9% 越界。`parse()` 当时根本没读 `Name` 字段（取的是 `f[8]` Effect），
所以这份答案一直在文件里、判据却看不见。

**3. 配色判据的形状与作品形态不匹配**

旧判据要求「存在**一对**占比 >=10% 且对比度达标」。它在逐字拉长、动画步进密的成品上失效：
无职 ED 有 135 种达标配色对，合计 **85.8%** 的事件都达标，但每一种只占 3.4%，
于是被判 FAIL，理由却是"无一对占比 >=10% 的配色达标"。

## Decision

三条判据全部改为**读取结构性事实**，不再依赖命名或单点统计。

**注音层**：`_furigana_by_structure()` 按三个跨作品稳定的语义特征合取判定 ——
字号显著小于主歌词行（`< 0.60` 倍）+ 文本纯假名占比 `>= 0.80` + 与其它文字事件时间重叠。
三条同时成立才算注音层，因此中文行/拉丁行不会被误认。

**特效贴合**：判定顺序按权威性 —— ① 文件自带 `assfx-band` 表 + `Name` 字段的 `fx:<band>` 归属；
② 无声明时回退到**同句墨迹包围盒**（该句全部文字事件外接矩形 + 5% 画面外扩），不是全文件一个标量。
该时刻确实没有歌词行的纯过场特效记入 `deco_skipped`，不参与比例。

**配色**：改量**达标事件占总事件的比重**（`min_readable_share = 0.50`），
不再要求某一对独占 10%。阈值取在实测分离面的空档里。

阈值来源（有效配色对中达标事件的占比）：

| 成品 | 达标占比 | 判定 |
|---|---|---|
| 东方 风祝 / 双版混合 | 100% | 合格 |
| 命运石之门 | 100% | 合格 |
| 无职 ED | 85.8% | 合格 |
| ヨスガ OP | 82.2% | 合格 |
| ちぃむ | 75.0% | 合格 |
| Charlotte | 70.3% | 合格 |
| ヨスガ ED（K 轴素材） | 28.0% | 不合格 |
| ときめき（负片风格） | 23.4% | 不合格 |

分离面是 70~100% 对 23~28%，阈值 50% 落在空档正中。

## 反验（判据不许只会放行）

改完必须证明判据**还拦得住**，否则是"把门拆了"而不是"把门修好"：

| 负控 | 注入内容 | 结果 |
|---|---|---|
| 空间 | 把 20% 的 fx 装饰锚点挪到 y=540 | FAIL，越界 19.8% |
| 注音 | 删掉全部 RB 事件 | FAIL，注音层样式无 |
| 配色 | 填充=描边=浅色（复刻 note 里的 1:1 真实失败） | FAIL，达标 0/6828 = 0% |
| 配色 | 填充压近黑 + 同步改样式表 primary | FAIL，达标 1171/6828 = 17% |

第一版修法**没通过**这组反验：当时把所有 `fx:` 以外的绘图事件直接跳过，
于是不带 `fx:` 命名的文件（命运石之门、Made In Abyss）装饰数变 0、判据永不触发 ——
一个永远 PASS 的判据等于没有。改成"无 band 声明时回退墨迹包围盒"后，
命运石之门仍以 0.8% 越界参与判定，ヨスガ ED 以 100% 被拦。

全库回归：23 份参与判定，**3 份由 FAIL 转 PASS**（ちぃむ、ヨスガ OP、无职 ED），
其余判定不变；应当不合格的（ヨスガ ED 的 K 轴素材、Made In Abyss 的 720p 参考作品）依旧 FAIL。

## Alternatives considered

**什么都不做，把这批成品加进豁免名单**：最强理由是「红线本来就拦参考作品，
新交付的也算特殊素材，加名单最快」。否决理由：豁免名单是给"不是本项目交付物的素材"用的
（K 轴、参照作品）。用户这两份是**要进播放列表的交付物**，把它们塞进豁免等于把红线
变成一张永远可以绕过的纸 —— 而这正是 `kfx-quality-redline` 当初要解决的问题
（"看不出错在哪，因为没有任何判据说它错"）。

**只放宽阈值（例如把"占比 >=10%"降到 >=3%）**：最强理由是「改动最小，一行数字」。
否决理由：这治的是症状。10% 这个形状对**预渲染式**成品（事件稀疏、每句一对颜色）成立，
对**逐字拉长式**成品（事件密、单对占比天然被摊薄）永远不成立；把阈值一路降到 3%
下次遇到摊薄到 2% 的照样误杀，而且会把真正没设计配色的作品一起放过去。
判据形状错了，改数字只是在移动那根错误的线。实测也印证：ヨスガ ED（确实不合格）
的最高对占比 72%，比无职 ED（合格）的 3.4% 高得多 —— **"最大对占比"与质量根本不相关**。

**把注音层判据维持样式名，只补一份常见名字白名单（RB/FURI/...）**：最强理由是
「几行就能修，且覆盖已知案例」。否决理由：note 里已经记过一次同类失败 ——
白名单、名字约定都不可靠（"各作品的命名毫无规律"，参照成品叫 `"OP JP 6-furigana"`）。
这次是 `RB`，下次是别的名字，同一个 bug 会第三次出现。结构判据一次解决并且可自证：
实测它在本仓全部 15 份成品上给出的结果与名字判据**一致**（有名字的地方一致），
在 `RB`/`FURI` 上额外正确地识别出注音，且没有把任何中文行/拉丁行误认成注音。

**保留"全文件 y 中位数"但改成"取歌词行的众数"**：最强理由是「仍然不需要读 Name 字段，
实现更小」。否决理由：它对**多带布局**依然无解。一个文件里日文/注音/中文本就是三条不同 y，
中位数或众数都只描述其中一条；而特效是**逐句**生成的，判定也必须逐句。
真正的修法是用 band 或同句墨迹盒 —— 这两者都是"逐句"的。

## Consequences

- `py/ass/quality_gate.py`、`py/music/kfx_gate.py`：注入层改为结构判定；
  空间判据改 band 优先 + 墨迹盒回退；配色改为达标事件占比。
  `RED` 新增 `min_readable_share` / `furi_size_ratio` / `furi_kana_ratio`
- `parse()` 现在返回 `name` 字段（原先丢弃 Name，导致 band 归属不可读）
- 新增 `_parse_bands()` / `_furigana_by_structure()`；`_KANA_RE`
- 用户的两份成品已按原样替换进 `static/music/`（未改动任何 ASS 内容），
  旧字幕备份为 `*.ass.bak-orig`；两份新成品所需字体已放入各自 `fonts/`
- 全库回归 23 份参与判定 / 3 份转 PASS，负控 4 项全部仍能拦住
- 已知边界：`min_readable_share = 0.50` 是从 8 份样本的分离面取的，
  样本量小；新增同类作品时应重新核对这张表，而不是假定 50% 永远正确
