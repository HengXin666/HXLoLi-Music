# Agent Note: 组合图形的尺寸口径必须按"参照边"归一化

Status: implemented

Decision-ID: karaoke-shape-size-baseline

- 工程侧用法: `dev/罪恶王冠/The Everlasting Guilty Crown/gen/common.py` 的 `art/art_run/art_pulse`

## Code

- `.agents/skills/hx-anime-karaoke-ass/scripts/assfx/layer/gen.py`
- `.agents/skills/hx-anime-karaoke-ass/scripts/assfx/layer/music/beat.py`
- `.agents/skills/hx-anime-karaoke-ass/scripts/assfx/text/anim.py`

## Problem

2026-10-03 做罪恶王冠 OP2 时, 三类"尺寸/时钟口径"问题各踩一次,
共同点是**同一个参数在两条不同的构造路径上含义不同**, 而代码没有任何地方说破:

1. **自绘路径与烘焙素材的量纲不同, 被当成同一个。**
   `shapes.py` / 番剧自绘件按**像素**构造（`crown_spikes(52)` 画出来就是 52px）;
   `assets/shapes.json` 的烘焙素材是 **200px 规范尺寸**（必须除 200 再给 `\fscx`）。
   第一版对自绘件又叠了一层 `\fscx{size}`, 于是 56px 的图形被放大成 **314px** 
   真渲染器截图里那团糊住整条带的光晕就是它。
2. **多体图形的"视觉尺寸"不该按最长边归一化。**
   修好量纲后改成"实测墨迹再归一化, 按最长边"  单体图形对了, 但**群像**错了:
   实测 `crowd(30, 6, spread=620)` 的原始 bbox 是 **641x41**, 按最长边归一化到 40px
   会把一簇人形压成 **40x2.5px**, 也就是一条细线。那不是"人群", 是"划痕"。
   同一问题的还有 `rails`(560x41) / `water_shimmer`(680x18) / `wave_line`(620x37) / `cross_chain`(760x53)。
3. **卡片 band 用行框估算, 而校验用的是实测墨迹。**
   `card()` 原先算 `y ± 0.62 * M.em(fs)`; 对 118px 的 TITLE 得到 y 585~993,
   而该行"文字+描边+模糊"实测超出这个范围  `validate_ass.py`（它用的是 `geom.event_extent`）
   于是报 `card:title` 越界 4 条。**生成期与校验期用了两套口径**, 必然吵架。
4. **`beat_drop()` 必然崩。**
   它写 `BEAT_SHAPES["streak"]`, 而 `bind_baked()` 只按 `_BAKED_SPEC` 的 8 个键填(不含 `streak`)。
   实测 `KeyError: 'streak'`  段落起爆层在整整一个工程里都是不可用的, 而调用方只看到异常。
5. **副文本的两个时钟是写死的常量。**
   `anim.py` 里注音固定 `+0.06s`、中文固定 `+0.20s`, 而设计表要求「副·出现」在整首里有 >=3 种取值
    表里写什么都不生效, 全曲 33 句走同一套默认值。

## Decision

- **尺寸统一到"实测墨迹 + 显式参照边"**: 发射口一律用 `S.size(draw)` 实测, 再按调用方指定的
  参照边归一化。单体图形按 `max(w,h)`; **群像/横条按 `h`**(新增 `fit="h"`)。
  判据: 29 个代表性图形在给定 size 下的实测墨迹必须等于 size(±3%), 实测 **29/29 通过**。
- **`card()` 的 band 取"估算与实测的并集"**。
  只信实测也不行: items 里的 `Metric` 是调用方给的, 可能与样式名声明的字体不是同一个
   实测 `dev/ヨスガノソラ/ツナグキズナ` 的卡片传 `MC`(文楷) 而样式名写 `TITLE`(明朝),
  两者宽度不同, 只按实测会让 band 比真实渲染窄、把原本通过的工程判成越界。取 `min/max` 并集后四工程全通过。
- **`beat_drop()` 改用 `shapes.py` 的手绘件**（`S.streak(26, 5)`）。
  它按像素构造、不需要 `\fscx` 归一化, 形态就是"细梭形光条", 正是那里的放射火花。
- **`Karaoke` 增加三个旋钮**: `rb_delay`(注音相对宿主字的秒差, 可为负)、
  `rb_out_lead`(注音比宿主早多久退场)、`cn_out_extra`(中文比日文晚多久退场)。
  这样设计表里「副·出现 / 副·消失」两列写的东西才真的能生效。

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **给自绘件也规定成 200px 规范尺寸, 与烘焙素材统一**: 最强理由是"一个口径最省心"。
  否决: `shapes.py` 的 89 个函数全是按像素构造的, 改它们等于改所有历史工程;
  而"实测墨迹"比"规定一个规范尺寸"更强  它对**任何**未来新增的图形都成立, 不依赖作者守规矩。
- **按最长边归一化, 群像就让它细**: 最强理由是"简单、可预测"。
  否决: `crowd` 存在的意义就是"数量感", 压成 2.5px 之后数量感也没了  那不如不画。
- **`card()` 只信 `event_extent`**: 最强理由是"与 validate 同口径"。见上, 会误伤老工程。
- **`beat_drop` 直接删掉**: 最强理由是"反正没人用它、也没测过"。
  否决: 段落起爆是"翻页"与"变密"的区别, 是设计上要用的; 而崩溃的根因只是一个键名。
- **副文本时钟继续用常量, 设计表那两列改成写"默认"**: 否决。那两列是判据
  (`check_gates.py` 查"取值 >=3 种")要求的; 把它们写成常量等于让判据变成形式主义。

## Consequences

- 罪恶王冠工程的 48 句里, 「副·出现」有 29 种取值、「主·逐字」有 43 种  判据与实现口径打通了。
- `beat_drop` 在 9 个段落边界各发 17 条, 实机通过。
- 已知边界: `fit` 只能在有明确"参照边"的图形上用; 混合群像(既宽又高)没有好答案,
  需要的话得给图形加一个显式的"视觉高度"声明。
- 已知边界: `art()` 的归一化是**按包围盒**的, 对带长细线的图形(如 `thread`/`rails`)
  仍会偏  所以才有 `fit="h"` 这个出口, 而不是指望包围盒万能。

## 追加: 三个只有机器能查的静默失效(2026-10-03 盲审发现, 已修)

盲审(独立子代理)在同一次交付里找到三处**不报错、目检也看不出**的缺陷, 全部已在源头修掉:

1. **`gen/common.py` 的 `"\frz"` 少一个反斜杠 → `\f` 是换页符 0x0C。**
   产出: 1341 个图形**画出来了、位置颜色都对, 只是没有旋转**(`\x0crz66` 被 libass 当空白吞掉)。
   像素级只差 0.14~0.46%, 任何目检都发现不了。
   **已加机器判据**: `validate_ass.py` 新增"事件文本含控制字符"检查  这是唯一能拦住它的东西。
   教训: Python 字符串里的 ASS 标签**必须写双反斜杠**; 同文件三处里错了一处, 说明"靠人守规矩"不成立。
2. **卡点/背景层的 band 用了 48 句并集, 装饰会落在译文行的行间。**
   修法: 两层各自限制到文字带**之外**的上下空白横条(`BAND_BELOW` 从 1006 起 / `BAND_ABOVE` 到 858 止),
   仍保留"跨句不停"的作用。修后文字带内这两层的事件归 **0 条**(盲审独立复现)。

   ⚠ **这条的量法本身是个教训, 值得单记**: 我第一版报"文字带核心像素被改变 4.42%",
   盲审报 0.00%, 第三轮又出现 11.20%  三个数字都不假, 只是**分母/阈值不同**。
   实测同一张对照图、同一时刻, 换窗口与阈值得到 **0.00% ~ 30.82%**(见下), 也就是这个量
   **没有稳定的判据意义**:
   | 口径 | 结果 |
   |---|---|
   | 矩形带 y980-1005, Δ>40 | 16.95% |
   | 矩形带 y980-1005, Δ>12 | 30.82% |
   | 矩形带 y802-1064, Δ>12 | 11.05% |
   | 矩形带 y860-1010, Δ>12 | 12.82% |
   | **字形墨迹(>120), Δ>25** | **0.00%** |
   唯一在两种口径下都成立的结论是: **字形墨迹改动 0.00%**  也就是"装饰从没压到笔画上"。
   所以正确的表述是"装饰穿过了译文行的**行间空白**", 不是"盖住了字"。
   **教训: 报一个"污染率"之前先证明它对本参数不敏感**, 否则那个数字只是那次测量的产物。
3. **"按最长边归一化"对群像/横条是错的。** 见正文第 2 点的 `fit="h"`。

另外记一条**判据边界的诚实结论**: 意境层本来就该在 band 内飘, 逐句层的主母题也挂在自己那句的
字附近  这是设计意图。判据只能停在"**字形墨迹零改动**"这一条(它稳定、可复现);
再往下("行间空白被装饰穿过"算不算问题)就是审美判断, 机械判据给不出及格线,
用门禁去代替那个判断只会让门禁变成噪音。
