# Agent Note: 门禁判据不能与被测实现脱钩

Status: implemented

Decision-ID: karaoke-gate-criteria-decoupled


## Code

- `.agents/skills/hx-anime-karaoke-ass/scripts/gate/check_lyrics_coverage.py`
- `.agents/skills/hx-anime-karaoke-ass/scripts/qa/validate_ass.py`

## Problem

三条判据各自都**说得出阈值**, 却指着错误的对象  于是它们既不拦真问题, 又稳定地报假阳性。
全部在 2026-10-03 的罪恶王冠工程上暴露, 且都是"改判据对象"而非"改阈值"才能修:

1. **`validate_ass.py` 的同步判据写死 `Layer == "3"`**。
   `assfx/core.py` 的 `ev()` 早就把 `ly:` 事件统一 `layer += 20`（"文字永远压得住特效"的结构保证）,
   所以高亮层实际是 **23**。写死 3 之后 `hlev` 只剩 FX 恰好落在 3 的极少数事件。
   实测同一份 ASS（逐字节相同, md5 `d474ba70da1d6848e0452ba3000c9009`）:
   旧报告报 8 条, 现在报 **482** 条  判据成了噪声源。
2. **同一条判据的粒度是"音拍", 而高亮层的粒度是"字"**。
   `anim.py` 的 `highlight()` 按**显示字**发事件(`hs = c["s"]`); 一个多音拍的汉字只有一个事件。
   拿 `timing.json` 的**音拍**逐个去找, "任何多音拍字的第 2 拍起"必然找不到 
   实测罪恶王冠 494 条、漆黑子弹 392 条, 逐条看全是 `mora>=1`, 一条真问题都没有。
3. **`check_fx_visible.py` 只走 ffmpeg 的 `subtitles=` 滤镜**。
   本仓库的 ass 会用到 `\1img` 这类 VSFilterMod 扩展, 而 `subtitles=` 遇到不认识的标签是
   **静默退化**（见 `steps/4-kfx/46-image/index.md`） 用它判"特效看不看得见"会给出与观众不符的低读数且不报错。
4. **`check_lyrics_coverage.py` 的"空档能量"判据会被人声分离残留骗过**。
   demucs 在纯器乐段仍从伴奏漏出 -18~-21 dB 信号, 与演唱段的 -18.6 dB 同量级,
   差 0~3 dB 正落在 `--db-tol` 里  7 处器乐持音段全被报成"疑似漏句"。

## Decision

**判据的层号/粒度/渲染器/信号来源, 一律从被测实现反解, 不许在判据里写常量。**

- `validate_ass.py`: 高亮层 = **`ly:` 事件里层号最高的那一层**。
  不取"出现次数最多"实测 Layer 21/22 各 3651 条是**底字层**, 按"最多"取会选错(命中 406/507);
  按最高层取则 **507/507 全命中**。理由: 高亮是叠在底字**之上**的一层, 必然层号最高。
  粒度改为按 `(line, unit)` 取首拍  那正是 `highlight()` 实际的发射粒度。
  并新增一条更强的判据: **整句一个字都没有高亮事件**才值得报警（单字缺失可能是别的机制在呈现）。
- `check_fx_visible.py`: 新增 `--renderer {ffmpeg,octopus}`, **默认 octopus**。
  两个渲染器在**同一份输入、同一个口径**下读数其实一致（实测同样 6 个时刻:
  ffmpeg 3083/3192/252/819/4957/3688 vs 定制版 3119/3159/262/863/5177/4412, 最大差 20%),
  默认取定制版是因为**只有它在扩展标签上不会静默退化**。
- `check_lyrics_coverage.py`: 判据 2 之后加两道独立裁决, 缺一不可:
  - **第二源交叉裁决**: 空档两端若分别被 LDDC 的句尾/句首贴住(±0.8s), 它就是真间奏。
  - **CTC 假名密度**(`ctc_kana_density`): 真在唱词 → 模型连续吐假名;
    只有器乐/长音 → 输出稀疏。阈值取**本曲演唱段密度的 p20**(自适应, 固定阈值在不同编曲密度下会失准)。
    实测: 演唱段 2.80~5.75 个/秒; 7 处空档 0.46~2.48; 纯器乐 0.00~1.50。
- 三条判据在证据不足时（缺 `kf.json` / 缺 `ctc_lp.npz`）**打印"跳过并说明缺什么", 不静默当通过**。

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **给 `validate_ass.py` 的同步判据加一个 `--hl-layer` 参数让调用方传**: 最强理由是"判据不该猜"。
  否决: 层号不是调用方的自由参数, 它是 `core.py` 的**结构保证**(`ly:` 统一 +20);
  让调用方传等于把这个不变量复制到每个工程里, 下次改 `+20` 又会全部失效。
- **把同步判据整个删掉（"反正假阳性多"）**: 最强理由是"它现在没区分度"。
  否决: 它拦的是一件真事  逐字高亮完全没发的事件。改成按字粒度后它在两个工程上都干净通过,
  而"整句没有高亮"这条新判据是任何别的检查都覆盖不到的。
- **`check_fx_visible.py` 保留 ffmpeg 作默认、octopus 作可选项**: 最强理由是"ffmpeg 快得多"。
  否决: 快 122 倍但**在扩展标签上会给出错的数且不报错**; 判据的正确性优先于速度,
  要速度就显式 `--renderer ffmpeg` 并自己确认该工程没用扩展标签。
- **给人声分离加"泄漏检测"再修 demucs**: 最强理由是"从源头解决更干净"。
  否决: 泄漏率依赖曲目与模型, 修不了根; 而"这段有没有词"是**可独立判定的**(第二源 + CTC 密度),
  不该依赖分离质量这个不确定的量。
- **把 `--db-tol` 调小以躲开残留**: 否决。实测空档与演唱段的能量差只有 0~3 dB,
  调到那个量级会把"真的漏句"一起放过。

## Consequences

- 四个工程的 `validate_ass.py` 从"稳定报几百条 WARN"变成全通过, 且现在真的能拦"整句没高亮"。
- `check_lyrics_coverage.py` 在罪恶王冠上从 FAIL 变成 PASS, 判决书里逐条写明每处空档的依据
  (6 处经第二源裁决、1 处经 CTC 密度裁决), 不是一句"通过"。
- 已知边界: 第二源裁决要求空档**两端**都被贴住; 长音句的尾巴会把一端推开, 于是它管不住
  "副歌尾长音之后那一段器乐"(实测 202.39-206.50 就是这么漏的)  这正是第三判据存在的理由。
- 已知边界: `check_fx_visible.py --renderer octopus` 每次启动一个 chromium, 慢得多;
  它与 `render_octopus.py` 共用 `/tmp/hxocto-work`, **并发跑会互相删除工作区**
  (实测并发时报 `ENOENT: .../frame036.png` 与 `mkdtemp` 失败)。并发时用 `TMPDIR` 隔离。
