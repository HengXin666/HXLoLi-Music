# Agent Note: kfx 快歌逐字让位 (交叠), 动作幅度, 舞台动作 (每首歌自己发明动作)

Status: implemented

Decision-ID: kfx-two-rows-and-stage-verbs

## Code

- `.agents/skills/hx-anime-karaoke-ass/scripts/kfx/kfx_song.py`

## Problem

ときめきアン・ドゥ・トロワ♪ 节奏快, 62 个行间空隙里 42 个 < 0.3 s. 单行轮换要求旧行退完新行才进, 新行只能在开唱前约 0.1 s 出现, 入场动画还没走完就开唱, 用户反馈 "出来的时候慢了一点".
用户还指出新歌的设计稿照搬了 オンリー 的动作组合 (斩 大斩 等): "给你的是方法论, 每次应该自己去调研, 自己创新出符合这首歌的东西".

## Decision

- 同目录同次改动: kfx_verbs_stage.py (新), kfx_verbs.py 动作表, kfx_build.py 全局字段, kfx_README.md.
- kfx_song: 先试了上下两行 (rows=2), 用户否决 ("不要弄成双行"), 已删除. 改为 `overlap` (设计稿 `交叠`, 默认 0 金样不变) + flow(): 仍是单行, 新行每个字在自己开唱前 overlap 秒进场, 旧行横向重叠的字提前 0.3 s 让位, 中文行在新行进场时直接切换 (cn_t). 实测 717 个字里只有 6 个进场不足 0.2 s.
- kfx_build: `幅度` (amp) 把动作轨的 dx dy rz sx sy 乘倍数 (用户嫌动作小), 入场 / 出场不变.
- 主菜 (用户 2026-11-23: "只有花没用, 要有一个主要的东西"): 先做了 连击 (尼娅出拳), 用户否决: 0:44 画面是三人并排跳舞 (手放脸颊, 左右踏步踢脚跟, 3 齐跳), 出拳不合意图, 已删. 改为 齐舞 / 齐舞·亮相 (kfx_verbs_stage): 数字是舞者, 唱到就跳起踢脚, 全组同侧踏步; 3 全组蹲下齐跳落地亮相变大定住; 最后一次亮相张开双臂 (行向两边散开). 用在 L15 L21 L48 L54. README 方法第 2 步: 每首歌必须有主菜, 且主菜要先看那一刻画面里人物在做什么.
- kfx_lyrics: 行首没有读音的记号 (「) 取第一个唱到的字的开始时间, 原来是 0 秒, 导致台词行整行在 0 秒排程.
- 新文件 kfx_verbs_stage.py, 7 个从这首歌 / 这部番调研出来的字上动作: 蹦 (ED 三人蹦跳), 换位 (1・2・3 舞者换位), 拳 (尼娅赤手空拳, 后一字被打歪), 礼 (令嬢屈膝礼), 碰 (茶会凑头), 映 (魔法映像开机), 猜拳 (ED 片尾猜拳). 只动字本身, 不画字外的东西.
- kfx_README: 方法改为 "每首歌调研并发明至少 3 个新动作, 旧动作只当配角", 快歌用两行.

## Alternatives considered

- 什么都不做: 快歌的行永远迟到, 新歌永远是 オンリー 的翻版, 不取.
- 复用现有方案 (单行, 缩短 enter / exit / handover): 空隙为 0 的行仍然只能在开唱瞬间出现, 治标不治本, 不取.
- 上下两行交替: 实现过, 用户否决.
- 整行交叉淡入: 两行字叠在一起看不清, 不取; 逐字让位只在同一位置换字.
- 把新动作写进 design.md 的自由描述而不进代码: 校验器和生成器都认不出, 不取.

## Consequences

- 交叠期间同一行里会短暂出现新旧两行的字 (旧行右半 + 新行左半), 约 0.5 s.
- 新工程的 timing.json unit 需与 kfx 记号编号一致 (README 坑 12).
- 新动作对所有歌可用; 金样 (オンリー) 逐字节不变, kfx_test.py ALL PASS.
- 以后新歌照方法: 先调研画面 / 歌词 / 角色, 发明动作, 再写设计稿.
