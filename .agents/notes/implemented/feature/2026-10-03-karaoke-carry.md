# Agent Note: 句间承接  跨句状态对象与可核对的承接量

Status: implemented

Decision-ID: karaoke-carry


## Code

- `.agents/skills/hx-anime-karaoke-ass/scripts/assfx/layer/carry.py`

## Problem

用户 2026-10-03 第一条意见: 「每 1 句上下文的关联…我们能不能做到这种关联性?」

实测确认这不是"做得不够", 是**结构上不存在传递通道**(漆黑子弹 ED, 33 句):

| 量 | 实测 |
|---|---|
| fx 首事件 == 该句 band 起点(±0.05s) | **31/33** |
| fx 末事件 == 该句 band 终点 | **33/33** |
| 每句图形种类(按绘图路径 md5) | 中位 **4**, 最小 1 |
| fx 事件终点晚于下一句 band 起点 | 31.3% |

六条边里四条在动, 但整段读起来是 33 个独立片段。那 31.3% 跨句事件是
`Generator` 的**退场淡出尾巴**(α 在降, 颜色/位置/图形全不变)  **不携带任何变量**。
`Generator.render()` 逐句循环, 每句独立构造 `FX(seed=1000+i)`、独立选色、独立定生死,
**句与句之间零状态**。

## Decision

新增 `scripts/assfx/layer/carry.py`: 一个逐句传递的 `Carry` 对象, 含五种**可核对**的量:

| 字段 | 含义 | 承接类型 |
|---|---|---|
| `color` | 末色 | 色温承接 |
| `x, y` | 末位置 | 位置承接 |
| `dx, dy` | 剩余动量 | 位置承接 |
| `shape` | 末图形 | 意象承接 |
| `energy` | 0~1 强度 | 语法承接(收/放) |

三个方法对应三种承接的**用法**:

- `entry(f, pull)`  入场接上上一句的动量与位置(位置夹进 band);
- `tint(base, k)`  把上一句末色混进本句基色, `k=0` 等于没有承接;
- `boost(level)`  同一意象**长一级**(`意象承接 ≠ 意象重复`: 加一级是承接, 原样再来是偷懒)。

`from_events()` 是关键: 从**刚刚发射过的事件**反解末状态(取最晚结束的那条,
读它的 `\move` 终点与速度), 于是"承接"不需要手写 `update`  只要生成器逐句
调一次 `carry.from_events(f)` 就自动成立。

判据仍是设计表里的那一条: **`承上` 的变量必须能在上一行的 `启下` 里找到同名项**.

## Alternatives considered

- **什么都不做, 靠"每句都用同一个母题"制造连续感**: 最强理由是"观众感知的是整体风格".
  否决(实测): 本工程 33 句**每句都有主母题且都不同**, 正是这个做法的结果 
  它保证了"每句都有意义", 却保证不了"句与句连得起来"。母题相同也不等于承接:
  同一个图形原样再用一遍是**重复**, 不是承接。

- **让 `Generator` 自动做承接, 不给上层对象**: 最强理由是"少一个概念".
  否决: 承接要传什么是**设计决策**(这一句留色还是留动量, 由词义决定),
  不是可以统一实现的机制。库只提供"传"的能力, "传什么"必须写在设计表里。

- **用"跨句事件占比"当承接判据**: 否决(实测): 本工程 31.3% 的事件跨句,
  看起来很好, 但它们是退场尾巴(色相/位置/图形全不变).
  只查时间的判据会被这个数字骗过。所以 `Carry` 传的是**值**, 不是**区间**。

- **把 carry 做成全局单例**: 最强理由是"省掉参数传递"。否决:
  一首歌里可能有并行的视觉线(主文本一条、背景一条), 各自要独立的 carry。

## Consequences

- 新增 `scripts/assfx/layer/carry.py`。
- 用法(生成器里):

      carry = Carry(color="#8A98A8")
      for P, ph in zip(PHRASES, phs):
          P["_carry"] = carry          # 本句可读上一句的末状态
          fx_fn(f, ph, k)              # 在 fx 里读
          carry.from_events(f)         # 写回本句的末状态

- 实跑验证: `Carry.entry()` 从 (1000,900) 与动量 (30,-12) 得到 (1010.5,895.8);
  `tint('#8A98A8')` 与末色 `#C02840` 混合得到 `#B04A5F`。
- 已知边界: `from_events` 依赖 `f.doc.events` 能按句切片; 现有 `FX` 没有 `_mark`,
  所以脚本里对没有该属性的情况**退回快照**(不报错, 但承接退化为"只传位置")。
  要做到逐句完整承接, 生成器需要在每句开始前记录 `len(doc.events)`。
