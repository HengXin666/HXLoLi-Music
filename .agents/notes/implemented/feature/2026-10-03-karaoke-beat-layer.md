## Problem

用户 2026-10-03 提了两件现有结构里**不存在**的事:

1. **伴奏层**: 「类似于歌曲的伴奏层次, 就是特效要随着伴奏来进行卡点…像 DJ 或者电音,
   音频可视化…跟着鼓点散」.
2. **图片层**: 「我们这个特效字幕是改版过的, 因此它应该是可以嵌入图片的,
   我们可以把一些图片作为左右元素在卡点的时候出现…你还需要抠图, 只要抠的完整,
   你不可能一个人抠了一半, 出来以后, 他的头发整个上边是平的一个矩形」.

第一件的根因是**触发源只有一个**: 所有特效挂在 `c["s"]`(人声音拍)上, 所以特效只会"跟唱"、不会"跟曲".

## Decision

### 卡点层 (40 + 44)

新增 `music_events.py`(伴奏 → 网格/起音/低频/段落) 与 `assfx/beat.py`(发射器).
规格全部来自**逐条量过**的参考成品(天使の3P「大切がきこえる」01:00 高潮段):

| 参数 | 实测 |
|---|---|
| 绘图事件 / 文字事件 | 3328 / 1516 = **2.2 倍** |
| 群发网格 | **0.125s 十六分**, 对齐误差中位 0.20(随机 0.5) |
| 群发周期比 | 八分 15 次 / 十六分 14 次 ≈ 4:1 |
| 起手缩放 → 成长 | **18%~40%** → 300ms 涨到 **63%** |
| 寿命 | 中位 1.09s, 均值 1.41s, >2s 占 23% |
| 存活密度 | 高潮段任一时刻**平均 64 条** |
| 颜色 | 同刻 **5~7 色并置** |
| 密度比 | 高潮 148~215 条/5s vs 主歌 43~75 |

**决定性证据**: 群发时刻与同刻字的音拍**零重合**  图形属于音乐, 不属于字.
这直接支持了用户说的「不是任何的文本」.

三条硬纪律写进契约: 不许长成"字"(它是伴奏触发, 必然与人声错位);
起手必须小(18%~40%); 同刻多色.

**调参中修掉的真实缺陷**: 第一版把小图形基准写成 4~9px 再乘 `fscx18%`, 实际只有 0.7~5.7px。
换算到 1080p 后, 参考的墨迹中位是 12.4×11.6px  **我方小一倍以上, 渲染出来看不见**。
`base_size` 改为 26~46px 的基准(乘 18%~63% 后落在 5~29px)。

交叉验证: 本工程独立算出 BPM **84.5**, 与既有 `grid.json` 的 **84.507** 一致。
反验: 起音与歌词音拍重合率 **79/665 = 11.9%**(换伴奏轨跑, `none` 占比应显著上升)。

### 图片层 (46)

新增 `cutout.py` + `assfx/image.py`. 两个实测规格:

1. **`\1img` 是填充纹理, 按绘制矩形平铺.** 矩形 = 图片尺寸时显示一次; 更大就铺 N×M 张
   (实测 300×240 矩形 + 105×84 图 = **9 张**). `put_image` 强制读图片真实尺寸.
2. **路径相对于 ass 目录, 且须先写进 worker 虚拟 FS.** 否则 `[vsfiltermod] Failed to load image: X (can't fopen)`,
   画面空白但**渲染不失败**  静默失败。

抠图判据(用户反例: "头发上边被切成平直矩形"):
四边 alpha 实色占比 ≤1% / 主体占比 8%~85% / 存在羽化过渡带 / 尺寸与矩形相等。
**反验样本(仓库内既有)**: 点兔 `Picture/tipi.png` → PASS(四边全 0);
`Picture/end/1.png` → **FAIL**(底部 alpha 均值 103.5、实色占比 46.93%, 正是"被切平"的样本)。

## 重做对照的实测数字(2026-10-03)

用本项目漆黑子弹 ED 重做一遍(输入文件完全相同):

| 量 | 未接新层 | 接了 |
|---|---|---|
| 卡点层事件 | **0** | **4073**(逐秒覆盖 86%, 同时存活峰值 53) |
| 背景层事件 | 0 | 290(覆盖 85%) |
| 图片层事件 | **0** | **4** |
| 事件总数 | 10190 | 14553 |
| **每句有彩填充色种类(中位)** | **1** | **12**(最大 36) |
| 高亮层填充色种类 | 17 | 587 |

**卡点层是净增的一层**: 每句 fx 事件中位两版都是 80, 卡点层没有从原有特效里挪走任何东西。

`music_events.py` 新增 `grid_fit` 自检: 起音对网格的归一化误差中位
(0.5 = 随机)。本工程实测 **0.051**  这一条同时证明了 BPM 与相位都对,
是"卡点层能不能往下做"的机械前置判据。

抠图侧修掉一个选型错误: `rembg` 默认用 `u2net`, 会**现场下载 1.02GB**
(实测卡在 4% 十几分钟); 本机 `~/.u2net/` 已有动漫专用模型 `isnet-anime.onnx`,
改它之后秒出, 且贴合更好(番剧是平涂色块 + 清晰轮廓)。
实抠一帧延珠: 四边 alpha 全 0、羽化过渡 20.31%、双马尾细发梢完整。

配色侧修掉一个真实缺陷: `make_hl_color` 取声部时写死 `mora=0`,
而 `voices.json` 的 key 是 `<line>.<unit>.<mora>`, 一个字可能**跨多个音拍** 
写死 key 时命中率极低, 声部色等于没生效。改为按 `ch["morae"]` 逐个查后生效。

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **卡点层不做独立层, 加进 `mood_bg` 里当一种新氛围**: 最强理由是"不用改生成器结构".
  否决(实测): 两者的**存在感曲线相反**  背景是平坦(宽、低、跨句), 卡点是脉冲(窄峰、高、跟网格).
  合成一层会让"空气"和"脉搏"互相吃掉。这是必须分成两层的数学理由, 不是审美偏好。
- **用瞬态强度直接调制逐字高亮**(即"字亮得更猛一些"), 不新开一层**:
  最强理由是改动最小、不需要新时间基。否决: 那仍然是"跟唱", 没有解决"跟曲"。
  参考成品的证据是**群发时刻与字音拍零重合**  真正的卡点感来自**错位**, 不是来自"更亮"。
- **卡点层用番剧元素**(红眼/莲)当图形: 最强理由是"与作品更相关".
  否决(用户直接指正): 「你不要是番剧元素, 因为突然出现一个人的话在这里作为卡点不是很好」.
  改用 10 种现代几何(四芒星/短光条/脉冲环/碎片/三角/六边形/菱形/弧/光束).
  番剧相关的图另有归宿  图片层, 且要少。
- **图片层不抠图, 直接用 MV 帧**: 否决(用户直接指正): 未抠的帧带背景,
  在字幕带上就是一个方块, 观感是"贴了张照片"。
- **抠图不做边缘体检**: 最强理由是"模型会给好结果". 否决: 仓库里点兔的 `end/1.png`
  就是一个**已经存在的**被切样本; 没有机械判据时它会被当好图用。
- **图片尺寸取整到 2 的幂 / 统一到 128px 再贴**: 否决(实测): 纹理按矩形平铺,
  矩形一旦不等于图片尺寸就会铺成多张  尺寸只能相等, 缩放要用 `\fscx/\fscy`。

## Consequences

- 新增 4 个脚本: `music_events.py` / `cutout.py` / `assfx/beat.py` / `assfx/image.py`.
- `setup_env.py` 的依赖表新增 `rembg` + `onnxruntime`(由 `cutout.py` 的 inline 块驱动);
  首次跑会下模型, 之后走缓存。
- 实跑数字: 卡点原型 194s 存活 55 条(目标 ≥40, 参考 64); 图片原型左右各一张提比 + 卡点图形同刻。
- 已知边界: `beat_scatter` 的 `per_beat` 与 `long_ratio` 是调存活密度的两个旋钮,
  换歌要重调; 判据是"任一时刻存活条数"而不是总事件数。
- `image.py` 的 `a_peak` 是 **alpha 值**(0=不透明, 255=全透明), 图片默认 8。
  (踩过: 传 255 得到全透明, 渲染空白。)
