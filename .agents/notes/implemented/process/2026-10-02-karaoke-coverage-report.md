# Agent Note: 歌词覆盖审计要落盘成门禁证据，元数据行按形状剔

Status: implemented

- 影响: `scripts/check_lyrics_coverage.py`（新增 `--report` 与 stdout 镜像落盘、元数据行剔除规则）

## Problem

漆黑的子弹 ED 工程（2026-10-02）跑到 `check_gates.py --stage render` 时撞上两件事：

1. **脚本跑了、结果 PASS，门禁却说"缺失"。**
   门禁读的是 `review/coverage.txt`，而本脚本只往 stdout 打 ——
   于是"跑过且通过"和"根本没跑"在门禁眼里完全一样。
   这条被写进 SKILL.md 的流程表（第 2 步之后跑），但没有任何一步会产生那个文件。
2. **元数据行被当成"漏句"。**
   用 KG 源时网络歌词的头两行是「トコハナ-やなぎなぎ(柳凪)」与「詞：やなぎなぎ」。
   原正则只认简体「词」与日文「作詞」，**不认繁体「詞」**，于是两行都被报成
   「网络有、本地没有」→ FAIL，而报错内容指不出到底漏了哪句歌词。
   同时标题行是按硬编码字符串（`"ツナグキズナ(" not in t`）剔的 —— 那只能对上一首歌。

## Decision

- **报告落盘**：`--report` 默认 `review/coverage.txt`，把 stdout **镜像**一份写进去
  （用一层 `sys.stdout` 代理，不改 `main()` 的任何逻辑，退出码原样透传）。
  门禁证据从此是"脚本自己产的"，不是"人抄一份"。
- **只有 `main()` 真的跑完审计才落盘**。判据是 stdout 里出现了结论行
  （`PASSED：歌词覆盖完整` / `FAILED：有漏句嫌疑`）—— 它们只可能由审计的末尾产生。
  提前退出（`--help`、参数错误、缺 `lyrics.txt`）时不写文件，并明说
  `未落盘：main() 没有跑完审计（提前退出，不是审计结果）`。
  原先无条件落盘，实测在 skill 目录里跑一次 `--help` 就会凭空长出一个 `review/coverage.txt`，
  里面是 usage 文本 —— 那正是这份门禁要消灭的"文件存在 ≠ 做过"。
- **`sys.exit("消息")` 不再抛 ValueError**：`e.code` 是字符串时打消息 + 返回 1。
  原先 `int(e.code or 0)` 会把一条清楚的"缺 lyrics.txt"变成一段 traceback。
- **元数据行按形状剔，不按歌名**：
  ① 制作人员行 = 中/日/英三语前缀 + 冒号（`作?[词詞]|訳[词詞]|曲|編曲|作曲|編|歌|唄|うた` +
  `Vocal|Lyric[s]?|Music|Arrange|Compose|Produced?`，大小写不敏感）；
  ② 标题行 = **含本曲曲名且长度 ≤40**（曲名由 `--title` 传入，不再硬编码）。

## Alternatives considered

- **什么都不做 / 让人手抄一份 review/coverage.txt**：最强理由是「脚本输出本来就能看懂」。
  否决：手抄会把"文件存在"降级成"某人记得抄过"，而门禁的整个意义是让"记不记得"不再相关。
- **让门禁改读 stdout 或退出码**：否决。门禁是**离线复核**用的（可能隔几天再跑一次），
  它读不到当时那个进程的输出；且退出码不携带"审计了什么"的内容。
- **把「詞：」这类行直接在 KG 源里过滤掉**：最强理由是「源头最干净」。
  否决：LDDC 返回的就是这些行，过滤放在源头意味着以后换源（QM/NE/LRCLIB）要各写一遍；
  而"哪些行不是歌词"是**与源无关**的性质，应该在消费端用形状判。
- **用长度阈值（≤12 字）剔标题行**：最强理由是「标题总很短」。
  否决（实测）：本工程标题行「トコハナ-やなぎなぎ(柳凪)」14 字，而正文最长句
  「この世で最高に綺麗なものはなんだか知ってる?」33 字 —— 阈值要卡在 14 与 33 之间很脆。
  「含曲名」这个判据既准又不依赖长度分布。

## Consequences

- 本工程：`review/coverage.txt` 由脚本产出，门禁 `PASS review/coverage.txt
  网络歌词逐句有对应，无疑似漏句空档`；网络比对从"跳过"（LDDC 依赖缺失或 QM 抽风）
  到真正跑过一次（KG 源 33 行）。
- 已知边界：网络比对**会因源抽风而跳过**（QM 实测返回 `错误码 2001`），
  此时报告里会写「跳过网络比对（原因）」，判据只剩"空档 vs 音频"那一条 —— 这不是静默降级。
- 繁体「詞」这条是**踩出来的**：非大陆歌词站用繁体很常见（本曲的 KG 源就是），
  正则必须覆盖 `词/詞/詞` 三种写法，否则会稳定误报。
- 提前退出的三种路径实测都不再落盘：`--help`、`--project /tmp/nonexistent_proj`（缺 lyrics）、
  以及 `--report` 指向别处时同样只在跑完审计后才写。
- 已知边界：判据是"stdout 里有结论行"，所以**改结论行的措辞就必须同步改这个判据**
  （两处字符串在 `main_reporting()` 里）。换来的是"usage 文本永远不会被当成审计证据"。
