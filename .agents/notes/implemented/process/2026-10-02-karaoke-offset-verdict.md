# Agent Note: 语音校准的判据要区分「检出噪声」与「真剪辑差异」

Status: implemented

- 影响: `scripts/calibrate_offset.py`（新增 `step_jump`、`dispersion_robust`、`--step-threshold`/`--outlier`）、
  `scripts/check_gates.py`（`check_offset` 读 `dispersion_robust`）

## Problem

`align_ctc --offset` 的输入来自 `calibrate_offset.py`，而它的判据是
「Δ 的 p90−p10 > 0.8s 就是拿错了版本」。漆黑的子弹 ED MV（2026-10-02）实测：

    能量法 Δ 中位 +0.130s、离散度 0.804s  → 判 FAIL
    CTC 法 Δ 中位 +0.129s、离散度 0.992s  → 判 FAIL

两条通道中位数一致到 1ms，说明**整体偏移是可靠的**，但都过不了判据。逐行看 Δ 才发现形状：
+0.23 / +0.43 / +0.41 / +0.13 / −0.43 / +0.26 / −0.43 / +0.34 … 正负交替、量级 0.4s。
这不是"两份音源剪辑不同"（那会在 Δ 上留一处**阶跃**：切点两侧各自稳定、彼此差一个常数），
而是**起唱点检测方法本身的噪声**：

- 行首是短促辅音时，能量/CTC 检出的起唱点落在元音上 → Δ 约 +0.4s；
- 行首是前一句长音拖过来时，检出点落在上一句尾 → Δ 约 −0.4s。

门禁在 `verdict.startswith("离散度过大")` 时判 FAIL，于是**这类工程永久卡死**，
而"卡死"的后果是有人去手改 offset.json 把判据糊过去 —— 比误放行更糟。

## Decision

判据从「单一离散度」改成「两条通道，任一通过即可，且**必须写明是哪一条通过的**」：

1. **稳健离散度** `dispersion_robust`：剔除 `|Δ−中位| > --outlier`（默认 2.0s）的行后再取 p90−p10。
   依据：整曲 MV 与 CD 版的分段差异是**已知的结构性差异**，且已被下游逐行锚点吸收
   （见 2026-10-02-karaoke-kf-line-pairing.md），不该由这一步拦。
2. **分段阶跃** `step_jump`：扫所有切点，取「两侧各 ≥8 行的中位数之差」的最大值。
   ≤ `--step-threshold`（默认 0.6s）说明 Δ 里**没有分段平移**，离散来自检出噪声。
   `check_offset` 与 `verdict` 都改用 `dispersion_robust`，并在 verdict 里注明通过的是哪条通道。

阈值不是拍的，是**合成数据标定**的（half=8）：

| 造出来的 Δ | step_jump | 判据 |
|---|---|---|
| 交替抖动 ±0.4（本工程实测形状） | **0.00** | 放行 |
| 分段平移（前 16 行 +0.1、后 17 行 +3.6） | **3.50** | 拦住 |
| 连续漂移（−1.2→+1.2 线性） | **1.24** | 拦住 |
| 随机换源（σ=1.5） | **2.30** | 拦住 |

## Alternatives considered

- **什么都不做 / 直接放宽 max-dispersion 到 1.0**：最强理由是「0.8 是拍出来的，本来就没标定」。
  否决：放宽到 1.0 会同时放行「连续漂移 1.92」这类真问题（上表第 3 行），
  而它恰恰是最需要拦住的一类 —— 那意味着整首歌后半段会整体偏 1s 以上。
- **手改 offset.json 的 verdict 字段绕过门禁**：否决。这正是门禁要防的行为：
  它把"判据不适用"这件事藏进了一个人写的字符串，下一个人只会看到 PASS。
- **改用互相关估计整体平移**：最强理由是「它一次用上整段音频，比逐行起音稳」。
  否决（实测）：steps/08-review-timing/impl/lag-verdict.md 已记录过 —— 谱通量起音投票法在周期性段落上会被
  吸到 +4.0s 的伪峰（真值 +1.901s）。逐行起音 + 中位数是本工程唯一验证过的通道。
- **把 Δ 序列的两端当"结构差异"直接切掉重估中位**：否决。切点位置是**推断**出来的，
  切错了会把整段的有效样本丢掉；而中位数本身就对两侧各半的偏移免疫（实测中位 +0.129
  与另一条独立通道（CTC / 能量）完全一致）。

## Consequences

- 本工程实测：`verdict = "同一剪辑，可用（离散 0.992s 超阈值，但 Δ 无分段阶跃 0.506s：
  离散来自起唱点检测的方法噪声）"`，门禁从 FAIL 变 PASS，而**判据没有被削弱** ——
  真分段/真换源三种合成样本仍全部被拦。
- 证据里多了三个可复核字段：`dispersion_robust` / `step_jump` / `step_threshold`，
  下一个人能看出"是凭什么放行的"，而不是只看到一个 PASS。
- 已知边界：`step_jump` 需要足够行数（`2*half+1 = 17` 行起），
  短歌或行数少的工程会返回 0.0 而落到稳健离散度那条通道上 —— 这是有意为之（宁可退回保守判据）。
