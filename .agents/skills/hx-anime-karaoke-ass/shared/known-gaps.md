### 经验 (定位类问题, 下次先做)

- 2026-11-09 p24 运动: 原判断"运动主要来自逐帧转阵"是错的. 实测转速 dps 70->20 运动几乎不变 (16673->16662), 地阵半径 200->120 只降约 5% (15740); 把 burst 的椭圆与斜光尺寸缩到 x0.5 运动直接降到 8949, x0.4 + r120 到 6079. 运动来源其实是 burst 件的面积, 不是转动. 教训: 运动/亮度超标时先做单因素消融 (每次只动一件: 转速 / 半径 / 单件尺寸), 量 p 句与邻句的 mv, 找到主因再改; 不要凭"它在转"就认定是转阵. 差分掩膜 (相邻两帧差异像素的位置) 先看它落在哪一块, 能更快缩小嫌疑.
- **libass 对 0 值的语义 (通用, 写任何 0 之前先查).** `\t(0,0,...)` 不是"立即", libass 把 t1=t2=0 当成整段事件时长. 实例 (2026-11-11 p31 护罩弧 v3->v4): `f.shape(fade_in=0)` 生成 `\t(0,0,\alpha..)`, 弧在整句 11s 里慢慢变亮, 207s 实测只有约四成亮度, 逐段生长的短事件和逐帧件还会每段闪一下; 肉眼只看出"发虚", 当时误以为是线太细. 规则: fade / blur / bord / `\t` 时间这类参数写 0 之前, 先确认 libass 对 0 的语义是"关闭"还是"到事件结束 / 取默认"; 要"立即"就写最小正值 (fade 写 0.01). 排查: 只渲染这一类事件 (加无效果的标记标签过滤出来), 量最亮像素, 和设定的 alpha 对不上就先查这个.
