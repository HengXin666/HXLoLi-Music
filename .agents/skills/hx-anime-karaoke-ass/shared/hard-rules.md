# 硬性规则(跨步骤, 最容易违反的)

这几条不属于任何单一步骤, 但每一条都踩过、都造成了返工. 动手之前先扫一遍

## 1. 完整版 + 高分辨率

先确认时长与官方完整版一致(不是 TV size 89 秒)、分辨率 ≥1080p, 再做后续所有步骤; 时间轴以最终 base 视频为准. **必须用 `scripts/source/find_source.py` 多源搜(B 站 + YouTube)**, 不要用 `yt-dlp ytsearch` 当唯一来源. **素材不达标就停下来反问用户要链接**, 不许自己挑一个 720p 凑合. 详见 `steps/1-source/01-source/impl/source-search.md`

## 2. 歌词一律从网络取, 禁止从视频画面识别字幕

网络同步歌词 > 歌词站文本+时间轴 > 纯人工听写(`--why`). **不许**用截图 OCR / 看帧抄词充当歌词来源  抄到的是「这一份剪辑剩下的字」, 且小字混淆的错会一路带到成片; 行数一错, 逐字高亮整句错位. 门禁只接受 `network` 与 `manual` 两种来源级别. 详见 `steps/2-lyrics/02-lyrics/index.md`

## 3. 位置对齐靠语音, 不靠画面

网络歌词时间轴与这份视频常差 0.1~0.5s, 用 `calibrate_offset.py` 从**人声**测出中位差. 离散度异常时先读 `steps/2-lyrics/03-offset/impl/verdict.md`, **不许手改 verdict**. 详见 `steps/2-lyrics/03-offset/index.md`

## 4. 原作内涵必须查, 不能只看 MV

番剧歌是原作的隐喻(主题曲/挿入歌/角色曲都是). MV 画面只说明"这一段在放什么", **原作内涵才决定"这一段该是什么情绪"**. `anime.notes.md` 必须回答四个问题: **内核、主题、与原作的关系(改编改掉了什么价值观)、情绪曲线**(要有访谈或乐谱出处). 实测教训: 只查角色表会让配色方向从头就错  某作的动画把原作"治愈的夏"改成了"寂寥的夏". 详见 `steps/3-anime-bg/10-anime-bg/index.md`

## 4b. `song-brief.md` 必填, 且每步动手前重读一遍

**在写任何一句特效之前, 先填 `proj/song-brief.md`; 之后每进入 `4-kfx` 的任一步骤, 先重读它**

四节, 缺一节就不许往下走:

```markdown
# 歌曲调研

## 番剧背景
## 歌曲纯歌词意境分析
## 歌曲在番剧背景下的分析
## 歌词特效
```

| 节 | 回答什么 | 判据 |
|---|---|---|
| 番剧背景 | 内核 / 主题 / 与原作的关系 / 情绪曲线 | 指向 `anime.notes.md` 的结论, 不只是角色表 |
| 歌曲纯歌词意境分析 | **不看画面、不看番剧**, 只读歌词本身: 在说什么、情绪怎么走、哪句是转折 | 必须指出至少一个转折点 |
| 歌曲在番剧背景下的分析 | 把上两节叠起来: **这首歌对应谁 / 哪段经历** | **必须点名至少一个角色名**, 且该名字能在 `anime.background.json` 的 `characters` 里找到 |
| 歌词特效 | 这首歌用什么策略, 指向具体条目 | 必须指到 `anime.elements.md` 的条目或 `design-table.md` 的句 |

**为什么单独要这份**: 实测代价  agent 跑着跑着就忘了这首歌在讲什么, 从第 5 句起退化成"按词义画图形", 与番剧无关. `anime.notes.md` 记的是**作品**, 这份记的是**这首歌与作品的关系**. 两者的差就是"这首歌是不是围绕某个角色写的"这一类判断  它决定绘图元素与风格该取谁的

例(说明怎么用, **不是可抄的答案**): 如果这首歌是围绕某角色整季的经历写的, 那么绘图元素与字体风格应该取**该角色的母题与应援色**, 而不是通用意象

## 4c. 写作规范(所有产物文件与代码注释)

用 **STE 受控写作**(ASD-STE100 的中文口径):

| 规则 | 上限 |
|---|---|
| 操作步骤的单句 | **≤35 汉字** |
| 描述性句子的单句 | **≤45 汉字** |
| 每段句数 | **≤6 句** |

- **只许用英文标点**(`.,;:!?()-` 与半角括号), 不许用中文标点
- **禁止表情符号**(emoji 与颜文字)
- 删虚动词: "进行优化" → "优化"; "做出决定" → "决定"
- 禁套话: 赋能 / 闭环 / 抓手 / 拉通 / 对齐颗粒度
- 禁含糊量词: 尽快 / 若干 / 大概 / 多次; 禁数字后的 "以上 / 以下 / 以内"
- **不许写得比做得好听.** 描述产物实际是什么, 不写愿景

判据: `hx-karaoke check_gates.py --stage design` 会扫产物文件的行长与禁用词

## 4d. 单个文件 ≤300 行

任何产物或代码文件**不超过 300 行**. 超了按**逻辑语义**拆, 不许按行数硬切

拆分判据: 一个文件只承担一个职责. 拆出来的部分各有自己的名字, 通过 import / 引用组合, 不许复制

## 5. 特效只能在 band 内  永久强制规则, 没有例外

band = 该句歌词块(注音顶~中文底、最左~最右)墨迹包围盒外扩 **(96, 54)px**(1080p 的 5%). **任何跑出 band 的内容都是垃圾, 一律不许交. ** 用户原话: 「永远画面只能有在字幕的 5% 附近的内容进行放, 这是永久的强制性规则. 任何内容违反就是垃圾. 」

这条不许被"为了效果更好看"说服. **已经因此被否掉的做法**(不要再试)

- ❌ 把特效当"画面背景层", 登记整幅画面的 band(`FULL_BAND` = 0,0,1920,1080)
- ❌ 两条丝带铺满画面、巨型心形结占画面 1/3
- ❌ "字幕左右两侧垂落的边框"(那也在 band 之外)
- ❌ 任何理由的"画面中部更空, 放那里更清楚"

**为什么它值得当铁律**: 目的不是"限制", 是让整片字幕退化成一个**固定矩形**.
播放器按内容包围盒逐帧算裁剪缩放, 位置一动字号视觉大小就跟着动(实测漂移 56.6%); 固定在 band 内则裁剪是常数、不需要 K 帧跟随, 也就没有画面的偏移震荡. **band 内 = 可直接裁剪**, 这是它不可协商的原因

所有绘图经 `FX.shape()` 发射(自动夹取), 每条事件 Name 写 `fx:<band>`; 最后 `validate_ass.py` 复核

## 6. 同位置交替

上一句基本走完(退场 ≥70%)再进场; 衔接紧时退场缩短到 0.2~0.3s 且不做逐字错落, 避免两句叠字. 由 `Generator.plan()` 自动处理, 不要手动叠两句

## 6b. 字幕只有一个位置: 水平居中 + 贴底

日文在上, 中文在下. **不许左右分栏、不许竖排、不许为躲画面而挪位**. 完整字幕的排版自由度只有两个: 字号与层级(注音/主/副), 没有位置自由度

**为什么**: 位置一动, 播放器按内容包围盒算出的裁剪缩放就跟着变(实测漂移 56.6%), 字号视觉大小会跟着抖. 固定居中 + 贴底 = 裁剪退化成常量矩形, 与第 5 条同源

**已因此排除的做法**(不要再试): 两侧竖排 STAFF 墙、左右分栏双语、贴边字幕条. 来源: p37 那份成品把 STAFF 表做成左右竖排(左 x109-319 / 右 x1030-1200, 全高), **在原 OP 底片上读着好看, 但不满足"固定矩形"**, 本项目不采用

## 6c. 中日等大, 注音小字, 副文本同大

| 层 | 字号 | 说明 |
|---|---|---|
| 日文主行 / 中文行 | **相等** | 中文不许比日文小  观众是中文用户, 中文是读懂层 |
| 副文本(回声/和声一行) | **与主行相等** | 那是**唱出来的**, 靠**颜色与特效**区分, **不靠字号** |
| 振假名(注音) | 主字的 **0.42~0.50 倍** | 这是唯一的例外: 注音必须小于主字, 否则压住汉字 |

实测依据: 本地成品里注音正好是主字的一半(主 48/注 24、主 36/注 18)。**「中文比日文小」是错的**, 已作废

## 6d. 中文行不做逐字, 靠「词对应」驱动

**中日语序不同**(日语主谓宾与中文顺序不一致), 按字对齐必然错位  要么对翻译要求极高, 要么让观众读不懂. 所以**中文永远不按字高亮**

三层机制, **从弱到强, 都要能用**:

| 层 | 机制 | 触发条件 |
|---|---|---|
| **L1 颜色对应** | 日文某词有颜色(承载含义), 中文里**对应的那个译词**用同一颜色 | 有词对齐关系即可, 最低成本 |
| **L2 特效同步** | 日文那个词有特效时, 中文对应词**同步出同一个特效** | 日文该词有特效 |
| **L3 整句按序** | 中文按**意群顺序**逐段出现(不是按字, 也不跟音拍) | 无词对齐关系时的兜底 |

**判据**: 中文的视觉**只能由"它对应日文哪个词"决定**, 不许由它自己的字序决定
- 词对齐关系必须是**设计阶段显式写下的一行数据**(写进 `review/design-table.md`), **写不出来就不许猜**  只能退到 L3 或纯色
- 中文层**可以完全没有特效**(只做 L1); 有特效时**必须是日文那次触发的复用**, 不许中文自己另想一个

## 7. 振假名逐字

`[冒|ぼう][険|けん]` 或 `[世界|せ.かい]`, 只有熟字训用 `[今日|=きょう]` 整体标注. 整词注音在长词上会偏离对应汉字. 用户明确要求逐字

## 8. 合いの手单独处理

整句括号的呼喊行标记为 call, 不参与切窗与对齐, 由特效函数呈现. 详见 `steps/2-lyrics/02-lyrics/impl/format.md`

## 9. 出片前必须过门禁

`check_gates.py --stage render` 退出码非 0 就不许渲染. 它是这些"不许跳"步骤的唯一机器判据. 详见 `steps/5-verify/13-validate/index.md`

## 10. 只准读 skill; 用户没指定参照物时, 禁止读任何本地非 skill 内容

**用户没有明确指定"参考某某"时, 一律不许去读本机上的其它内容**  别的历史工程(`dev/` 下的任何其它目录)、别的仓库、别的成品 ASS、别的媒体文件, 全部禁止

理由(实测代价, 2026-10-03): 本文件与 `impl/per-line.md` / `impl/three-layers.md` / `impl/density.md` / `47-color` 里曾有一批**指向别处工程**的话(「读三个参考工程得出」「其余历史工程在 dev/… 下」「用本项目某工程重做过对照」), 于是 agent 照着去读, 把那个工程的做法当成了"标准值"抄进新工程  而那个工程本身是错的. 结果: 配色、图形尺寸、密度全部被污染, 整轮产物作废重做

因此
- **默认参照物只有机制, 不是成品**: `steps/` 里写下的规则与阈值、`shapes.py` 这类**图元原语**、以及 `templates/` 的骨架. 除这些, skill 内不再有"可对照的成品"
- **`examples/` 与模板里的具名示例不是标准答案**. 任何具体图形(心形 / 裂纹 / 具名道具)、任何具体配色、任何具体句子都是**某一次的产物**, 只许用来理解"这个机制怎么回事", **不许照抄进新工程**. 照抄 = 拼贴, 既无创新也可能侵权
- **要参照 skill 之外的东西, 必须由用户点名**("参考 XXX")  点名之后也只读那一个, 不外扩
- 文档里凡是出现"参考工程实测值"的数字, 都只许当作**该文档的结论**引用, **不许按路径去读它的原始产物**(路径可能已经不存在、或那份产物本身是错的)

## 10b. 判据不许拍脑袋定阈值

**任何门禁判据, 必须先在一批真实成品上跑过、确认它有区分能力, 再写进门禁**

理由(实测代价): 曾有一条"同一首歌内图元种类下限"的判据, 拿 12 份真实成品一测, **判掉了 8 份生产级作品**. 后来发现几何种类数的分布是 2 到 2608  这个量根本没有区分能力

所以定阈值前先做两件事: (1) 在正例上跑, 看会不会误杀; (2) 在反例上跑, 看会不会放过. 两样都没做过就不许写成 FAIL, 最多写 WARN

## 11. skill 目录不带任何一次运行的痕迹

**任何工程的产物都不许存进 skill**: `lyrics.txt`、`timing.json`、烧好的 `shapes.json`、
下载的 SVG 缓存、MV 帧、成片  全属于**工程目录**. skill 里只有代码、契约、模板与一份保留示例

判据: `git status` 之后 skill 目录下不该出现任何一次具体制作的产物. `bake_shapes.py` 会拒绝 `--out` 指向 skill 内部, `svg2ass` 的缓存也不落在 skill 里(见 `steps/4-kfx/42-text-main/impl/precise-shapes.md`)
