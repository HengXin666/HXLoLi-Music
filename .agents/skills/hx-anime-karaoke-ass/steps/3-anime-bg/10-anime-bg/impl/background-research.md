# 番剧设定考据: 六类必查检索与 notes 写法

只看 MV 画面 + 一次泛搜就下结论, 特效只能做到“好看但空洞”: 同样是守护主题,
知道角色设定的人会画魔女帽/契约红线/比翼单羽, 不知道的人只能画通用星星与光点.
两者在技术上都是合法的 ASS, 差距全在**内涵**上 —— 而内涵只来自读设定.

所以这一步是**强制的**, 产物是 `anime.background.json`(机器证据)+ `anime.notes.md`(人读的结论).
`check_gates.py` 查两者: json 存在且非空; notes **必须存在且 ≥500 字**, 缺文件判 FAIL、
缺必答问题判 WARN(见 §4 与脚本注释里“为什么语义质量不做机械 FAIL”).

## 0. 这一步到底在找什么: 歌是原作的隐喻

**番剧歌不是独立的音乐作品. ** 它按用途分三类, 三类都要求先读过原作:

| 类型 | 例 | 没读原作会怎样 |
|------|----|---------------|
| 主题曲 OP/ED | ヨスガノソラ OP「比翼の羽根」 | 不知道「比翼鸟一目一翼, 单只飞不起来」是全作母题 → 画不出“成对”骨架 |
| 挿入歌 / 剧中歌 | ヨスガノソラ 挿入歌「ツナグキズナ」 | 不知道动画与原作价值观相反 → 把“寂寥的夏”画成“温暖的夏” |
| 角色曲 | 各角色 image song | 分不清这是谁的视角 → 用错角色的符号 |

**判据**: 曲名与歌词里几乎一定有对**标题 / 角色名 / 作品固有词**的呼应.
先把它找出来 —— 那个呼应就是“歌词”与“画面”的接点, 也就是你要做的“感情对照”.

一句话分工: **MV 画面告诉你“这一段在放什么”, 原作内涵告诉你“这一段该是什么情绪”. **
缺了后者, 后面十二步全做完, 也只能出一份技术正确、但不对味的字幕.

## 0.5 先看邻居, 再动手搜

同一个番可能已经做过别的歌. **先查本 skill 的 `examples/`, 再查工程区 `dev/<番名>/*/anime.notes.md`**:

```bash
grep -rl "<番名>" <skill>/examples/*/anime.notes.md dev/*/*/anime.notes.md 2>/dev/null
```

命中就**必读**, 并在自己的 notes 里写一行**继承声明**: 继承了哪几条母题、为什么这次不同.
跨曲引用本来就是本 skill 的加分项 —— ヨスガノソラ ED 正是靠这一条, 把 OP 的比翼母题
用一根**红线**接到歌词的「ヨスガを頼りに」上. 没读过同番工程的人做不出这个连接,
反而会把已有资产丢掉、再重造一个更差的.

## 1. 抓结构化条目(bgm.tv)

```bash
hx-karaoke fetch_anime_bg.py --project proj --anime "ヨスガノソラ" --song "比翼の羽根"
# 条目不确定时先看候选表，再 --bgm-id 指定
hx-karaoke fetch_anime_bg.py --project proj --anime "無職転生" --bgm-id 287982
```

实测(2026-10-01, 未带 token): `--anime "ヨスガノソラ"` → 条目 id 7157、简介 198 字、**26 个角色全部带中文简介**.
所以 `--bgm-token` 只是提高限额, **不是**跳过这一步的理由.

产物里要用的是三样:

- `summary` —— 故事前提. 决定了 OP/ED 的情绪基调(乡间夏日 / 轮回 / 复仇).
- `characters[].summary` —— **每个角色的设定细节**. “沉默寡言、深居简出、病弱”直接给出可画的视觉母题.
- `name_cn` —— 中文译名, 写卡片文案时用.

⚠️ **`summary` 是故事前提, 不是主题. ** 主题要去 §2.5 那些地方读.

## 2. 读梗与用语(萌娘百科)

萌娘百科的 `api.php` 实测返回 `{"error":{"code":"action-notallowed"}}`(只放行白名单 UA),
**不要在这上面浪费重试**. 改用抓页面正文:

```bash
# argo_fetch 是本机一等工具，遇 JS/风控会自动升级浏览器渲染
#   抓 https://zh.moegirl.org.cn/<条目名>，focus 用你要查的东西
```

实测两条踩坑(2026-10-01): `action=raw` 被 robots.txt 拦; `缘之空_(动画)` 这个条目**不存在**
(返回的是“找不到页面”的正文, 不是内容 —— 别把它当资料). 用主条目名.

要查的通常是这几类(它们才是卡片与非字面特效的来源):

- **用语/梗**: 作品特有的词(“缘”的多义、角色口癖). 写进间奏卡比复述 MV 标语有价值.
- **角色关系**: 谁与谁是双子/主从/宿敌 —— 决定“成对图形”(双羽、两光点、红线)用在哪句.
- **章节结构**: 集数表能给“剧情走到哪”的时间感, 判断某句词对应哪段剧情.
- **作品的公开主题解读**: 只当参考, 不照抄; 与 `summary` 冲突时以官方简介为准.

## 2.5 检索清单: 六类必查, 一条都不能省

`fetch_anime_bg.py` 只回答“角色是谁”. “**作品在讲什么**”要另外查. 下面六类, 检索词直接复制去跑
(日文优先, 命中率最高); **不要只搜“<番名> 剧情”**.

| 找什么 | 检索词 | 得到什么 | 写进 notes 哪一节 |
|--------|--------|---------|------------------|
| 作品解读 / 考察 | `<番名> 考察`、`<番名> 感想 テーマ`、`<番名> レビュー` | 主题、母题、演出手法 → **配色与明暗的依据** | 内核 / 主题 |
| 官方访谈 | `<曲名> インタビュー`、`<アーティスト> インタビュー` | 创作者自述的意图与听点(**权威度最高**) | 曲子在讲什么 |
| **改编差异** | `<番名> 原作 アニメ 違い`、`<番名> 原作との違い` | **动画有没有改掉原作的价值观** | 与原作的关系 |
| 题名考据 | `<番名> タイトル 意味`、`<番名> 語源` | 标题的多义, 往往与歌词同源 | 内核 / 卡片文案 |
| 舞台原型 | `<番名> 聖地巡礼`、`<番名> 舞台 モデル` | 实景地点 → 该画什么样的风景 | 母题组 |
| 乐谱 / 结构 | `<曲名> コード`(chordwiki)、`<曲名> 転調` | 段落划分 + 转调点 = **情绪曲线的机械证据** | 曲子在讲什么 |

再补两条:
- 歌曲信息(发售日 / 收录曲 / 作编曲): `<曲名> シングル 収録` 或 uta-net 的歌詞页面.
- 播出位置(这首歌在每话的什么位置): `<番名> 各話 エンディング 挿入歌`.

**读了但没记出处 = 等于没读. ** 每条结论都要能指回具体来源(§3 的「来源」一节).

实测有效度(2026-10-01, ヨスガノソラ): 上面六类**全部命中**, 其中三条改变了设计方向 ——
“改编差异”挖出动画与原作反向对置, “题名考据”挖出标题与歌词同源, “乐谱结构”挖出两次转调.
这三条**没有一条**在 bgm.tv 的角色简介里.

## 3. 落成 `anime.notes.md` —— 四个必答问题

下一步(8b 逐句设计)会直接引用这个文件. 模板:

```markdown
# <番名> 设定与母题（<曲名>）

## 内核
一句话：这部作品在讲什么。

## 主题
1~2 句，**标明出处**。（例：比翼鸟必须并肩才飞得起来 —— 全片母题是"成对"）

## 与原作的关系
改编作品必答：动画相对原作**改掉了什么价值观**？（例：原作是"靠小镇的縁走出去"，
动画是"舍弃縁、两人独自沉沦"。）非改编作品写一句"原作即本体，无改编差异"。

## 曲子在讲什么
- 这是谁的视角、隐喻了谁的处境
- 曲名 / 歌词对**标题、角色名、作品固有词**的呼应（= 与画面的接点）
- 情绪曲线：逐段落写（段落 → 调 → 情绪），要有出处（访谈原话或乐谱转调）

## 角色 → 视觉母题
| 角色 | 设定关键点 | 可画母题 | 图形库对应 |
|------|-----------|---------|-----------|
| 春日野穹 | 病弱、深居简出、与悠是双子 | 成对光点、白羽单翼 | bird, feather, thread |
| 天女目瑛 | 神社、巫女 | 注连绳、铃 | ring, rune_ring |

## 母题组
不属于某个角色的场景符号（夏日乡间 / 纸艺布景 / 茶色餐桌…），以及各自的使用判据。

## 继承声明
同番已有工程时必写：继承了什么、为什么这次不同。

## 画面时间线（每 1.5s 抽帧得到）
| 时间 | 画面 | 主色 | 亮/暗 | 可用的既有母题 |

## 来源
每条结论对应的 URL 或文件名。

## 未核实项
查了但没查到的，明确列出。**不许用推测填空。**
```

## 4. 判据(不满足就别进 `steps/4-kfx/42-text-main`)

- `anime.background.json`: **summary 非空 且 角色 ≥6**(`check_gates.py --min-chars`). 少于此说明抓错了条目.
- `anime.notes.md`: **必须存在**且 **≥500 字** —— 缺文件或只写占位, `check_gates.py` 判 **FAIL**.
- notes 缺“内核/主题”或“与原作的关系”、或没写出处 → `check_gates.py` 判 **WARN**(点名缺哪一节).
  改编作品缺“与原作的关系”最要命, 但它影响的是**方向**不是**格式**, 所以用 WARN 点名而不是 FAIL 拦截.
- ⚠️ **语义质量不做机械 FAIL**. 判“这四个问题答得好不好”要么靠人读、要么靠模型判,
  都不是可证伪的检查; 硬设成 FAIL 只会催生“为了过门禁而写的空标题”——那比不写更糟.
  门禁只保证“做了、有出处、不是占位”, **答得对不对由 `steps/4-kfx/42-text-main` 的设计表反向追责**:
  设计表里每句的配色若指不到 notes 的情绪曲线, 就是 notes 没写到位.
- notes 必须引用**至少一条外部解读来源**(访谈 / 考察文 / 官方资料). 只有 bgm 简介 = 没查内涵, 判 WARN.
- “角色 → 视觉母题”表里, **每首歌的关键句至少能指到一个母题**; 指不到的那几句,
  要么回去补查, 要么承认它只是氛围句(并在设计表里写明是氛围句).
- **情绪曲线必须有出处**: 哪段暗、哪段亮, 要能指到访谈原话或乐谱转调, 不许凭感觉.
- 卡片内容与 MV 自带文字**不重复**: MV 已打英文标语时, 卡片写词源/设定/人物.
  判据: 把卡片文案与逐帧抽出来的画面文字对一遍, 重复的删.

## 5. 实例: ヨスガノソラ「ツナグキズナ」的完整链条

这是**一份合格 notes 该有的密度**的样本(调研 2026-10-01). 四问逐条对上.

**内核**: 这部作品讲的是**孤独**, 以及两个失去父母的人在被世界看见与只有彼此之间的选择.

**主题 / 题名的三层**:
| 层 | 内容 | 出处 |
|---|---|---|
| 副题 | `In solitude, where we are least alone.` | 拜伦《Childe Harold's Pilgrimage》**Canto IV 第 XC 节** |
| 汉字表记 | 「**縁の空**」 | ja.wikipedia |
| 语源 | よすが = 拠り所 / 身寄り / 血縁者 / **身を寄せる所** / 頼りとする人 | 古語辞典 |

拜伦那句的下文形容这种连结用的动词是 **binding(系)**、意象是一条 **zone(腰带)** ——
而曲名「ツナグキズナ」的「繋ぐ」正是 binding. **歌名是拜伦那句诗的日译. **

**与原作的关系(本作最关键的一条)**: TV 动画把原作的价值观**整个翻了过来**.

| | 原作游戏 | TV 动画 |
|---|---|---|
| 奥木染这个小镇 | 伤心二人**治愈伤口**的温暖场所 | **寂寥感**弥漫的场所 |
| 与小镇的縁 | 靠它**向前走** | **舍弃**它, 两人独自去找幸福 |
| 穹线走向 | — | 共依存地**一起堕落**, 退废而非纯爱 |
| 色调 | 柔和亲切 | **偏硬、寂寥** |

→ 所以方向是「**寂寥的夏**」而不是「温暖的夏」: 刺眼却安静的午后、蝉声、空掉的餐桌、
旧木廊、深绿的湖. 穹线后期的视觉语汇是「**茶色い食卓とレトルトパックの残骸**」——
**进入后半段, 色温要往下压到茶色**, 不能全程维持清新夏绿.

另有一条演出提示: 本作演出被反复形容为“洋画的” —— 短台词、人物站位、
**玻璃上倒映的表情**、背景小道具承载信息. → 特效做**玻璃反光 / 水面倒影**这类安静的叠影,
不要做大而喧哗的东西.

**曲子在讲什么**:
- 曲名对标题的呼应: **縁**(よすが)与**絆**(きずな)是同一个东西的两个名字.
  歌词第 10-11 行说破了 —— 「縁がいつか名前変えても / 確かめ合えたその意味を**変わらず呼ぶよ絆と**」
  (即使“縁”有一天改了名字, 彼此确认过的那个意义我依然称之为“絆”).
  “改名”这个动作, 就是标题与曲名之间的关系. **这一句是全曲脊椎, 特效重心必须落在这里. **
- 硬链接: 游戏开局悠的自我介绍用了「**寄す処**を求めて」, 而歌词第 3 行是「**寄す処**での夏の日」.
  标题、游戏台词、歌词, 三处同一个词.
- 官方对影像的定性(ja.wikipedia 引官方 OFFICIAL CHARACTER BOOK pp.56-57):
  「挿入歌のアニメーションは、**悠と穹の過去を描き、2人の生い立ちや引っ越した経緯がわかる内容**」.
  → 开场三句「果ては懐かしい季節 / 明日を求めた / 寄す処での夏の日」配**回忆**, 是有官方依据的, 不是解读.

**情绪曲线(有机械证据)**: 访谈里 nyanyannya 说全曲走向是
「**切なくさびしい → 明るく爽やか**」, 听点是「**最後のサビでの転調**」. 乐谱证实且比他说的还多一次:

| 段落 | 调 | 时间 |
|---|---|---|
| 主歌 A | **Cm** | 15.6s「果ては懐かしい季節」 |
| 主歌 B | Cm 续 | 93.7s「錆びて消えない孤独の寂しさを」 |
| 副歌 1 | **D 系** | 135.3s「優しさの中に小さく咲いた」 |
| 副歌 2 | **E♭ 系** | 199.7s「広い世界で僕らのことを」 |

→ **Cm → D → E♭ 就是“暗→亮”的曲线本身. 配色与亮度跟着这两级台阶走, 不要凭感觉. **

**播出位置**: 每话结构是 本編 → **ED1(挿入歌＝ツナグキズナ)** → ミニアニメ(初佳篇)→ ED2(ももクロ).
所以它每话都接在最沉重的时刻之后. 注意: 官方频道把它标成 “エンディング”,
制作名单写的是 “**挿入歌**” —— 两者不矛盾(占 ED 的时段, 性质是挿入歌), 以制作名单为准.

**未核实项(不填推测)**: 本曲在正片中具体出现在哪一话哪个场景, 没有逐话记录;
官方挿入歌影像公开渠道只有 95s 的 TV size, 完整版在 BD 特典的「ノンクレジット本編挿入歌」里.

## 6. 反面例子(本仓库实际踩过)

- ❌ 只搜“<番名> 剧情”拿一段百科简介 → 每个角色都只能画通用心形/星星, 30 句特效靠换配色撑.
- ❌ 把 OP 画面里的“角色背影”当主角 → 那其实是配角, 特效画错母题(画了剑, 实际那集讲的是离别).
- ❌ **跑完 `fetch_anime_bg.py`、填完“角色→母题”表、门禁 PASS, 就当这一步做完了. **
  实测(2026-10-01, ヨスガノソラ「ツナグキズナ」): 26 个角色全拿到、表格填满、门禁绿,
  但完全没读作品**在讲什么** —— 结果把“寂寥的夏”设计成了“温暖的夏”,
  配色方向从头就错. **角色表只能让特效“看得出是谁”, 决定不了“这一句该亮还是该暗”. **
  当时的门禁判据只有 `角色数 >= 6`, 拦不住这种失败, 所以现在加上了 notes.md 的存在性与内容检查.
- ❌ **不看已有的同番工程就重头搜** → 同一个番可能已经有两份做好的 notes(含“跨曲红线引用”这种高级做法),
  却从零开始查, 既丢掉现成资产, 又大概率做得更差.
- ✅ 查完 bgm 角色表 + 六类检索 → 发现“成对”是全作母题、动画把原作翻了过来、情绪曲线由两次转调决定
  → 每一句至少有一个“两个元素”的图形(双羽、两光点、并肩线), 副歌换成“两元素靠近/分离”的动画语汇,
  后半段压成茶色. 这类设计读者说不清为什么, 但会感觉“贴”.
