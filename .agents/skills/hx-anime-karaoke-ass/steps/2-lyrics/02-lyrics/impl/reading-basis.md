# 读音基准必须来自语音识别, 不是词典

**本文是结论沉淀. 读到此处即止, 不要重新推导. **

## 症状

某个汉字的振假名标了"标准读音", 但那句字幕整体的起拍与演唱**系统性错位**
(通常差 0.5~1 秒, 且只错这一句). 因为读音音素数不匹配, CTC 被迫把时间均摊, 于是每个音的起点都偏.

## 根因

歌词站/词典给的是**标准读音**, 歌手唱的是**实际读音**. 两者不一致是常态:
汉字词的熟字训、当て字、演唱者刻意的读法. 用词典当基准 = 拿错的先验去喂对齐.

## 判据: 用 `ctc_read.py` 读「模型听到了什么」

```bash
hx-karaoke ctc_read.py stems/vocals16k.wav stems/ctc_lp.npz 71.5-76.0
```

输出是逐帧贪心解码的假名 + 时间, 括号内是次优候选. **这就是演唱的实测读音. **

实测一例: 标了 `[縁|えにし]`(标准读音), 但 `ctc_read` 在这段读到
`71.78す(つ) 72.20ぎ(き)` —— 音形是 **よ-す-が**, 不是 え-に-し. 改成 `[縁|よすが]` 后该句归位.
(旁证: 本番剧标题官方汉字即「**縁**の空」, 读 ヨスガ —— 这是作者埋的梗, 占位词与题名同源. )

## 修法(把语音识别前移到标注阶段)

1. **先跑 `ctc_read`, 再定读音**. 对每个"看起来可能有特殊读法"的词, 读一遍它的 CTC 输出:
   - 音素数对得上且音形相符 → 标注正确, 继续;
   - 音素数量对不上(如 4 音节只对齐出 2 个)→ **读音标错了**, 按 CTC 音形改写.
2. 高风险词清单(优先核): 熟字训、当て字、人名、含「縁/絆/寄す処」这类番剧专属词汇、
   以及任何长度 >3 且读音不规则的和语词.
3. 判据不是"词典这么写", 而是"**这个读音能否让 CTC 对齐出与演唱一致的音素数**".
4. 三方互证顺序: **CTC 听音 > 原 MV 自带注音 > 词典/歌词站**(词典只在 CTC 听不清时才作兜底).

## 注意 CTC 的边界

实测 `ctc_read` 在**清晰独唱段**(如首句)可靠; 在**唱腔/和声/快节奏段**会大量串音, 输出无意义(连续错误候选). 所以:

- 只在清晰段采信 CTC 读音;
- 对串音段, 用它做**音节数**核对(数量对不上仍是强信号), 不要用它定具体假名.

## 接入点

这一步在**标注阶段(最前)**, 早于对齐: 读音基准错了会污染对齐,
对齐错了又会让长音判断失真. 顺序不能换.
