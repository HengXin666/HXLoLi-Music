# 代码依赖与 G2 (验收台 v3)

验收台让 agent 改生成器代码. G2 隔离要回答 "这次改动会牵动谁". 答案来自生成时的动态追踪, 不靠静态分析.

## 清单里多了什么

`<out>.manifest.json` 由 `assfx/layer/trace.py` 补充:

| 位置 | 字段 | 意义 |
|---|---|---|
| 单元 | `deps.code` | 生成这个单元期间执行过的工程函数 (`文件:顶层名`) |
| 单元 | `deps.data` | 单元数据的哈希 (句单元 = PHRASES 的那一项, 卡片 = 文案与位置) |
| 单元 | `deps.window` | 出入场规划牵动的下一句 (沿用 v2) |
| 单元 | `emit` | 每个函数发出的事件数, 层, 时间范围. 验收台用它把问题路由到函数和源文件 |
| 句单元 | `chars` | `[字, 起, 止, x, 宽]`. 选区的字下标就是这里的下标 |
| 顶层 | `code.fns` | 每个函数的文件, 行号, 哈希 |
| 顶层 | `code.entry` | 单元范围之外执行的工程函数 (如 `main`, `cards.title`) 和它名下的单元 |
| 顶层 | `code.data_names` | 登记为单元数据的常量名 (如 `make_ass.py: PHRASES`) |

## 规则

- 工程代码 = 生成器脚本所在目录下的 `.py`. skill 的 `scripts/` 是库, 不记. 改库走 regress
- 单元范围: `Generator.render` 每句一个, `Generator.card` 一个. 工程自己画的层 (卡点/背景/图片) 要用 `with G.scope(key):` 包住. 没包住的函数记为 entry
- entry 函数改了: 影响它名下的单元. 名下没有单元, 按全部单元算
- 函数哈希 = 函数所在顶层语句 (函数或类) 的 AST, 去掉 docstring, 加上它引用的模块常量的 AST. 常量顺着同目录的 `from X import` 找, 最多两层. 改注释不算改代码
- 单元数据常量 (PHRASES) 不进函数哈希. 改第 i 项, 只预测第 i 个句单元 (以及它的 window)
- `ASSFX_TRACE=0` 关闭追踪. 追踪开关不影响 ASS 输出 (逐字节相同, 自测里有这一项)

## 改代码的流程 (`scripts/accept/accept.py`)

1. `begin`: 改代码前存基准 (raw, 清单, 工程 `.py`)
2. 改代码
3. `predict --scope <问题单元>`: 列出改了的函数, 预测影响集, 波及的 "好". 影响集超出问题范围时:
   - 默认分叉: 把共用函数复制一份给问题范围用, 原版不动
   - 必须全局改: verify 时 `--declare <单元> --why <理由>`, 这些句子全部重跑自审
4. `verify --scope ...`: 重跑生成器, 三条硬核对:
   - A. "好" 不许是 touched. 声明也不能豁免
   - B. 实际变了的单元 <= 问题范围 + 声明
   - C. 实际变了的单元 <= 预测影响集 + 输入变了的单元. 否则追踪漏了依赖: 修追踪, 不许放行
   失败: raw 恢复为基准, 这次输出留在 `review/accept/base/fail.ass`. 通过: 构建 out.ass, 新输出成为下一次的基准

## "好" 的冻结

- 快照是保证: `good` 把选区当前的事件存为快照. 构建 = 删掉生成器输出里同选区的事件, 放回快照
- 指纹是报警: 单元 `fp` (句单元) 或清单 `inputs` (其他单元), 加 `deps.code` 各函数哈希与 `deps.data`
- 状态: `ok` 生成器新输出与快照相同; `touched` 不同而输入没变 (代码碰到了 "好", G2 判越权); `stale` 输入变了 (时间/歌词), 快照照旧, 请用户重看, 不自动替换
- 粒度: 选几个字时冻结与这些字相交的事件. 事件按 `\pos`/`\move` 起点落在哪个字框里判. 没有位置的事件覆盖整句. `good` 会报出实际冻结范围
