# 5 门禁检验

## 这一组只做拦截

前面三组产出输入, `4-kfx` 产出成品, **这一组决定"能不能交"**

| 子步骤 | 关心什么 |
|------|---------|
| `13-validate` | 硬门禁 + 自动校验 + 可见性(退出码非 0 = 不许出片) |
| `14-inspect` | 抽帧目检(**必须用真渲染器**) |
| `15-render` | 封装出片(外挂 MKV / 烧录 MP4) |
| `16-blind-review` | **开子代理盲审**, 按判据独立打分; 不过门槛不许出片 |

## 顺序不是可选的

    13 门禁 -> 14 目检 -> 16 盲审 -> 15 出片

**16 必须在 15 之前.** 盲审没过就出片, 等于把"用户来当评审"当成流程的一环  实测代价是用户连提三次同一个问题(特效太多 / 图形粗糙 / 尺寸太大), 而每一次都返工重出

## 盲审为什么必须是子代理

主代理是设计者, **会替自己的设计找理由**. 2026-10-03 的实测: 门禁 6/6 通过、自评"效果更好了", 用户看完连提三次问题. 盲审的价值不是"多一双眼睛", 是**切断作者为自己辩护这条路径**  子代理没参与设计, 它读到的只有判据与数字
