## 自动校验(validate_ass.py, 必须"通过")

- [E] band 越界: fx/ly/card 事件包围盒(含缩放、旋转透视、边框、模糊、clip)超出 band
- [E] band 未登记 / 超出画面; [E] 字体缺失(只统计真正渲染文字的样式); [E] 时间非法
- [W] 歌词同屏重叠 >1.2s; [W] 音拍在高亮层无对应起点; [W] 事件密度过高(>900 同时事件); [W] 未标注 Name 的事件
- 包围盒估算已用 libass 实渲染对拍(`geom.py`): 绘图精确到 1px; 旋转按 9 点投影(透视距离 312.5px)取并集, 偏保守

## 特效可见性(必查, 最容易被忽略)

band 只是**上限**不是目标尺寸. 实测踩过: 某工程 clamp 仅 10 次(看着很守规矩), 但图形尺寸只有同款示例的 1/10(`S.shard(R,5)` vs `r*2.6`)、`a_peak` 中位 110(示例 150~210), 结果 FX 层单独渲染时整帧只有 35~1144 个亮像素  **特效等于不存在**, 而 validate_ass 照样判通过

所以校验通过 ≠ 看得见. 判据

- [ ] **FX 层单独渲染**: 把所有 `Name: fx:*` 事件单独抽成一份 ass, 纯黑底渲染几个关键句
      统计亮像素. 整帧 <2000 亮像素说明太淡太小, 要加大尺寸或提高 `a_peak`.
- [ ] **尺寸参照**: `streak` 长 90~180 / 线宽 3~6; `thread` 线宽 >=3; `shard` 半径 >=15
      `sakura/sunflower/maple` 单个 16~70. 低于这个量级在 1080p 上就是一条看不见的细线.
- [ ] **透明度**: 字后特效(Layer 0)`a_peak` 150~210; 字前(Layer 5~8)才可压到 60~120
- [ ] **不要反向理解 clamp**: clamp 少不等于设计好  也可能是特效缩得太小根本没碰到边界
- [ ] **不要只按「字」铺量, 要按「音拍」铺**(2026-10-02 漆黑的子弹 ED 实测)
      `burst`/逐字层是按**字**发射的、寿命只有 0.7~1.4s, 而一个字常占 2~4 个音拍(长音),
      于是**长音中间出现空窗**  实测 23 个抽样时刻里判"太淡"的 6 个中有 4 个正好落在长音中间
      (143.0 / 150.0 / 157.0 / 231.0s). 修法是加一层「按音拍起飞」的持续元素(每个音拍起点放一颗、
      寿命 1~1.8s), 或给整句铺一层常驻柔光(`f.glow` 从 t_in 到 t_end).
- [ ] **常驻柔光要压住量级**: 整句柔光把帧内亮像素从 ~3000 顶到 4 万(差一个数量级)
      画面会被冲白  可读性优先于"够亮". 实测 a_peak 58~62 + blur 26~28 + 半径只比 band 大 10px
      是合适的量级(仍然把帧内亮像素从 ~1900 抬到 ~25000 的只有它一个, 但叠加在实拍画面上看不出白幕).
      判据: **亮像素 >=2000 是下限, 但没有上限阈值, 靠抽帧目检看有没有盖住画面主体. **

## 人工目检(snapshots.py, 每句至少 1 帧, 高潮句 2~3 帧)

## 踩坑记录

| 现象 | 原因 | 解决 |
|------|------|------|
| YouTube 下载要求登录/bot 校验 | 风控 | 改用 B 站等来源; 搜源一律走 `find_source.py` 多源, 不要只搜 YouTube |
| 只搜 YouTube 导致「找不到完整版」 | `ytsearch` 不覆盖 B 站 | 实测 `ytsearch10` 返回 10 条全是 YouTube id. `find_source.py` 已并接 B 站 API |
| 拿到 720p 就往下做 | 没有达标判据, 自己降级 | 脚本最高分 <40 就反问用户要链接; 素材不行后面 11 步全白做 |
| 系统 ffmpeg 无 libx264, openh264 报错 | 编译选项 | 只影响烧录(`hx-karaoke render_burn.sh`). 先跑 `ffmpeg -encoders | grep libx264` 确认; 没有时用静态版 ffmpeg, 或 libass 渲染 → rawvideo 管道 → x264 |
| MKV 封装报 "has no mimetype tag" | 字体附件没带 mimetype | `render.sh` 已按扩展名填 `font/ttf` / `font/otf` / `font/collection` |
| 播放器不显示外挂字幕 | 字幕轨没设 default, 或播放器不支持 ASS | 用 mpv / VLC / PotPlayer; `render.sh` 已设 `-disposition:s:0 default` |
| 注音离字太高 | `\an5` 按行框居中, 字体 win 度量大 | calibrate_ruby.py 实测墨迹 |
| 阴影层入场后"突然变实" | 入场用 `\alpha&H00&` 覆盖了层自身 `\1a/\3a` | 淡入目标写该层自己的 1a/3a(anim.target_alpha) |
| 句尾被截、下一句首被吃 | 对齐窗口按 lrc 时间硬切 | 在换气空隙/能量最低点切窗 |
| 一串音拍挤在 0.1s 内 | CTC 在长音/连唱处塌缩 | 频谱人工摊开, 参照网格与副歌一致性 |
| 绘图整体偏左上 | libass 绘图原点=对齐框左上 | shapes.norm() 归一化 |
| 大魔法阵倾斜后畸变/爆出画面 | libass 透视距离仅 ~312px | flat() 预压扁 + floor_spin 逐帧转 |
| 带 \org 的特效被夹取后飞出 | 平移了 pos 没平移 org | FX.shape 同步平移 \org |
| 缩小后校验仍越界 | 估算把 100% 当成下限 | 以静态初值为基准(strip_t) |
| lrc 时间整体偏移 | 版本/前奏不同 | align_ctc --estimate-offset |
| MV 中段出现其它曲目的硬字幕/站点水印 | 录屏源 | 掩膜对比定位时段 + delogo 分段启用 |
| libass 找不到 "Arial" | 纯绘图样式也声明了字体 | Doc(fx_font=已有字体) |
| 个别句子早 ~0.3s | CTC 把句首辅音/气声当起音, 或吸附到前一格 | check_sync A 类 → 频谱确认 → fixes |
| 合いの手行把前一句腰斩 | 按呼喊行的 lrc 时间切了窗 | 整句括号 = call 行, 不参与切窗/对齐 |
| 快歌里几拍挤在 20ms | CTC 在齐唱/rap 塌缩 | grid_align.py(网格槽位 DP)|
| 副歌两次节奏不一样 | 各自独立对齐、各自出错 | grid_align `--parity` 联合对齐; parity_cmp 复核 |
| BPM 只有实际一半 | beat_grid 测到半拍 | `--div 8` 代替 16 分的 div 4 |
| 卡片两端被切 | 宽度估算没算样式 Spacing; item 字号没生效 | gen.card 读 Spacing; look 标签带 `\fs` |
| 多个绘图叠在同一点 | `FX.shape` 会 norm() 居中, 图形里写的偏移丢失 | 每个部件用 x/y 单独定位 |
| 文字特效校验越界(初始小缩放) | FX.text 按初始标签(如 \fscx30)量尺寸, 放大后才越界 | 自己按最终尺寸预先夹取中心(见 yosuga_ed `burst_box`)|
| `\fry`+`\org` 包围盒估算巨大 | 透视投影 | 用 `\fscx` 收缩 + t_move 模拟翻门 |
| 退场越过注音上沿 | 无注音句的 band 较矮, rise 退场超出 | 该句 `ext="fade"` 或减小位移 |
| 抄了 MV 硬字幕当歌词, 行数/内容与网络版不符 | 没走来源定级, 直接看画面抄 | 走 `find_lyrics.py`(网络优先); 门禁用音拍数比对 `timing.json` 与 `lyrics.txt` |
| 歌词时间轴整体差 0.2~0.5s | 网络歌词的前奏剪辑与手上的视频不同 | `calibrate_offset.py` 的中位差 → `align_ctc --offset`; 离散度 >0.8s 说明不是同一剪辑, 换源 |
| 能量法测出的起唱点整体早 0.3s | 上句长音拖过来, 被当成"从静音起来" | 换 `calibrate_offset.py --ctc`(看发音本身, 不看能量) |
| 想靠抄 MV 硬字幕省事 |  | 硬性规则禁止: 画面里的字不作为歌词来源. 走 `find_lyrics.py`; 歌词站拿不到就人工听写 + `--why` |
| lrclib 报 503 就以为"这首没有" | 服务偶发不可用 | 脚本已重试 3 次; 真拿不到再走歌词站文本或 `--register-manual --why` |
| 抓到的番剧条目是同名后续季度 | 按番名搜的第一个不一定是这一季 | 看候选表里的播出日期再 `--bgm-id` 指定; 角色数能拿来对(ED1 应抓 2021 年第一季) |
| 特效每句都像同一种图形 | 没读设定, 只有 MV 画面 | 跑 `fetch_anime_bg.py` + 写 `anime.notes.md` 的角色→母题表, 设计表按它填 |
| 短片段上 GPU 比 CPU 还慢 | CUDA 上下文初始化开销 | 别用 12s 片段下结论; 用 `device_check.py` 看单次调用耗时与整曲场景 |
