# 歌词来源定级：定序、证据与各源实测可用性

## 定序（不许颠倒，也不许绕开）

1. **网络同步歌词**（lrclib，带时间轴）—— 首选。`find_lyrics.py` 自动打分挑版本。
2. **歌词站纯文本 + 时间轴** —— 次选。日文歌词站常有**逐字振假名**，照抄切分能省掉大量查字典的时间。
3. **纯人工听写** —— 最后。必须 `--register-manual --why "..."` 写明为什么前两级都拿不到。

**禁止从视频画面识别字幕**（截图 OCR / 看帧抄词）—— 这条不是偏好而是硬性规则，理由：

- MV 里的硬字幕常被裁切、被台标水印遮挡、本身是 TV size 删减版 —— 抄到的是「这一份剪辑剩下的字」，
  不是作品本身；
- 画面 OCR 对小字混淆严重（し↔つ、は↔ば、促音脱落），而它出的错不会自己暴露，会一路带到成片；
- 特效字号/逐字高亮依赖**精确的音拍数**，多一个字少一个字都会让整句错位，而 OCR 恰好在字数是不可靠的。

网络歌词拿到后按 `format.md` 补逐字振假名与中文。

## 时间轴的本地校准（这才是「本地识别」该做的事）

网络歌词的时间轴是 CD/完整版的，与手上这份 MV 常差 0.1~0.5s（前奏剪辑不同、是否含 TV 前奏）。
用**人声**把这个差量测出来 —— 识别**时间**，不识别**文字**：

```bash
uv run $S/calibrate_offset.py --lyrics proj/lyrics.txt --vocals proj/stems/vocals16k.wav --out proj/offset.json
uv run $S/calibrate_offset.py --lyrics proj/lyrics.txt --vocals proj/stems/vocals16k.wav --ctc --out proj/offset.json
```

两条证据通道：

- **能量/起音**（默认，快）：在人声里找每次「从静音起来」的起唱点，与歌词行的 lrc 时间配对求差。
- **CTC**（`--ctc`，慢但准）：对每行窗口跑 wav2vec2 强制对齐，取该行**第一个音拍**的模型起点。
  能量法在「上一句长音拖过来」或「器乐残留」时会误判，CTC 看的是发音本身（默认走 GPU）。

判据写在产物里：**中位差就是 `align_ctc --offset` 的值**；**离散度**（Δ 的 p90−p10）>0.8s
说明网络歌词与这份视频不是同一剪辑 —— 换一份同源时间轴，或退回人工听写并写 why，**不许硬套**。

历史工程（人工校时已吸收整体偏移）可以用 `--from-timing proj/timing.json --why "..."` 据终稿反推，
但必须写明 why —— 它给的是「当时用了多少」，不是「这次该用多少」。

## 产物与门禁

- `proj/lyrics.source.json`：来源、URL、抓取时间、行数、**正文 sha256** 与**时间列 sha256**。
  两条指纹分开记的原因：正文一定会被人工补注音改掉，时间列不该被改。
  门禁比对时间列指纹 —— 「补注音」不会被误报成换了来源，「偷偷挪了某句时间」会被抓住。
- `proj/offset.json`：语音校准结果（中位差 / 离散度 / 逐行 Δ / 判据结论）。`check_gates.py` 会查。
- 手工来源必须带 `--why`：缺 why 时门禁判 FAIL，因为它区分不出「查过没有」和「懒得查」。

## 取到网络歌词之后

1. 照 `format.md` 补 `[漢|よみ]` 逐字振假名（歌词站有逐字 ruby 时直接照抄切分）。
2. 自译中文，贴合歌意与番剧语境，不要机翻腔。
3. 读音以**实际演唱**为准（歌词站标的是朗读音，演唱常不同：`[本気|まじ]`）。
4. 行数是硬的：门禁会比对 `timing.json` 的音拍数与 `lyrics.txt` 的音拍数，
   对不上就是用了两份不同的歌词。

## 实测记录（2026-10-01）

- lrclib `/api/search?q=`：J-pop 命中率高，`syncedLyrics` 常带；**会偶发 503**，
  脚本已重试 3 次 —— 不要把一次的 503 当成「这首没有」。
- lrclib 的 `instrumental` 字段偶有缺失，标题里带 Instrumental/オフボーカル/伴奏 的靠标题过滤。
- B 站 `x/player/v2` 的 `subtitle.subtitles` 多数稿件为空（实测官方 MV 也是空），
  不要指望它当歌词来源；它只对「投稿人自己传了 CC 字幕」的稿子有用。
- 萌娘百科 `api.php` 实测 `action-notallowed`；用页面正文（见 `steps/10-anime-bg/impl/background-research.md`）。
- ⚠️ **`source` 字段是「来源级别」，不是「引擎名」**（2026-10-01 修）。`find_lyrics.py` 直出曾把
  `source="lrclib"` / `"local-lrc"` 写进证据，而 `check_gates.py` 只认 `network`/`manual` ——
  **照文档第一条命令跑完，门禁必 FAIL**，且报错只说「来源级别不合法」，看不出是工具自己写错了。
  现在引擎名挪进 `engine`，`source` 恒为 `network`/`manual`；旧文件用
  `--adopt --source-kind network --why '...'` 重登记即可。examples 的三个工程当初都 `--adopt` 过，
  所以没暴露这个 bug —— **只有从零跑一遍才会撞上**。
- 能量法实测（20s 合成人声，3 行）：3/3 行测到起唱，Δ 完全一致（离散 0.000s）—— 干净人声下它足够准；
  连唱/长音重叠时才需要 `--ctc`。
