# 44 卡点层设计(跟音乐, 不跟字)

## 只做这一件事

给整首歌铺一层**跟着伴奏事件走**的脉冲层. 它不挂字、不做信息, 只做情绪强度.

## 实测的既定规格(来自参考成品, 逐条量过)

参考: 天使の3P「大切がきこえる」01:00 高潮段.

| 参数 | 实测值 | 说明 |
|---|---|---|
| 网格 | **0.125s**(十六分) | 群发对齐误差中位 0.20; 随机应为 0.5 |
| 群发周期 | 2 格(八分) 15 次 / 1 格(十六分) 14 次 | 约 4:1 |
| 单次群发 | 3~10 条(峰值 23) | 高潮加倍 |
| 起手缩放 | **18%~40%** | 不是 100%; 从满尺寸开始就没有"爆发" |
| 成长 | 300ms 涨到 **63%** | 快 |
| 单条寿命 | 中位 1.09s, 均值 1.41s, **>2s 占 23%** | 双寿命族 |
| 运动 | 从原点螺旋外扩, `frz` 1500ms 转 300~600° | |
| 颜色 | **同刻 5~7 色并置** | "颜色区分"的真实出处 |
| 存活密度 | 高潮段**任一时刻平均 64 条** | 决定观感的第一参数 |
| 密度比 | 高潮 148~215 条/5s vs 主歌 43~75 | 3~5 倍 |

**尺寸口径(最容易搞错的一条)**: 参考的 `fscx18%` 是相对**它自己画的大路径**,
换算到 1080p 的墨迹中位是 **12.4 × 11.6px**.
第一版把小图形基准写成 4~9px 再乘 18%, 实际只有 0.7~5.7px —— **差一倍以上, 渲染出来看不见**.
所以 `beat_scatter` 的 `base_size` 默认给 **26~46px**, 乘 18%~63% 后落在 5~29px.

## 图形选型(用户 2026-10-03 定的方向)

「具有区分的, 然后应该是比较现代的…你不要是番剧元素,
因为突然出现一个人的话, 在这里作为卡点不是很好」

所以卡点层用**现代几何**: 四芒星 / 短光条 / 脉冲环 / 碎片 / 三角 / 六边形 / 菱形 / 弧 / 光束.
**不用番剧元素**(人物、道具)—— 那属于图片层(`46-image`), 且要少.

## 四条硬纪律

1. **不许长成"字".** 它是伴奏触发, 必然与人声错位; 一旦看起来像文字,
   观众会拿它判断"唱到哪了", 结果是觉得字幕错了. 只做光 / 粒子 / 形变 / 位移.
2. **起手必须小.** 18%~40%, 不是 100%.
3. **同刻多色.** 一次群发里 5~7 种颜色并置.
4. **柔光预算: 同一个带里最多一层大 blur.** 实测失败模式(2026-10-03):
   每句 fx 里已有 `f.glow(blur=30~46)`, 卡点层再叠一层 blur=24 ——
   三层柔光叠在同一个 758x242 的窄带里糊成一片雾, **把逐字多色整片盖掉**.
   分工: 背景层用大 blur(>=20), 卡点层 <=10, 每句特效的柔光只留一处且 blur<=22.

## 怎么用

```python
from assfx.beat import MusicEvents, beat_scatter, beat_pulse, beat_drop, beat_sink
ME = MusicEvents.load("proj/review/music-events.json")
beat_pulse(f, ME, k.t_in, k.t_end, level=L, layer=0, colors="sunset", every=4)   # 拍级呼吸
beat_scatter(f, ME, k.t_in, k.t_end, level=L, colors="sunset", per_beat=(7,14))  # 卡点群发
# 段落边界才用, 全曲几次:
beat_drop(f, ME, t_section_start, level=3, colors="sunset")
```

## 关卡: 必须用**真渲染器**目检

```bash
hx-karaoke render_octopus.py proj/out.ass --out proj/review/beat/ --times 60,120,195
```

**不要用 ffmpeg 截** —— 本机 ffmpeg 的 libass 不支持 VSFilterMod 标签,
判定"图片/纹理能不能用"会得到完全错误的结论(实测渲染成纯色白块).

## 过关条件

- `hx-karaoke check_fx_visible.py` 在卡点密集处的亮像素达标(整帧 ≥2000, 良好值 2 万~3 万).
- **任一时刻存活条数 ≥40**(参考 64; 低于 40 画面读起来是"稀稀拉拉几个图形").
- 目检: 图形**不排成一条横线**(垂直分布要铺开 band 高度的 ~60%).
- 与 `07-grid` 的 BPM 一致(实测 84.5).
