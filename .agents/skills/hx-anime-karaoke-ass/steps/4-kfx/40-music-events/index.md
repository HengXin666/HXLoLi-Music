# 40 音乐事件表(卡点层的输入)

## 只做这一件事

把**伴奏**抽成一张时间表, 作为卡点层的触发源. 产物 `proj/review/music-events.json`

## 为什么需要它

现在所有特效的触发源只有一个  **人声音拍**(`timing.json`, 来自对人声轨的 CTC 对齐). 特效挂在它上面, 所以特效只会"跟唱", 不会"跟曲"

参考成品(某专业成品的高潮段)实测: 群发间隔落在**十六分网格**上, 而**群发时刻与同刻字的音拍零重合**  图形属于音乐, 不属于字

## 命令

```bash
hx-karaoke music_events.py --inst proj/stems/inst.wav --out proj/review/music-events.json \
    --verify --vocals proj/stems/vocals16k.wav --timing proj/timing.json
```

`--bpm-hint` 只在自动测不准时给. 正常情况让它自己从起音间隔推

## 四类事件与各自用途

| type | 判据 | 用来做什么 |
|---|---|---|
| `onset` | 谱通量局部峰 | 瞬态迸发(鼓点) |
| `grid` | 十六分/八分网格点 | **卡点层的主要时间基** |
| `sub` | 低频能量峰 | 下沉 / 重量感 |
| `section` | 长窗能量台阶 | 段落边界(与 chordwiki 转调点互验) |

`strength` 是每个起音的归一化强度, 生成器按它决定**单次群发条数**

## 过关条件

- `--verify` 输出里 **起音与歌词音拍(±40ms)的重合率应显著低于 100%**. 实测 79/665 = **11.9%**(人声分离干净的正常值). 若显著偏离, 先怀疑人声分离质量. 重合率过高(>60%)说明**伴奏轨里还有人声泄漏**  回 `04-vocals` 重分, 不要往下做
- BPM 必须能与 `07-grid` 的 `grid.json` 对上(实测两处独立算出都是 **84.5**). 对不上说明起音抽错了, 不要往下做
- **`grid_fit` 必须 < 0.30**(脚本自检输出). 它是"起音落在网格上"的归一化误差中位, 0.5 = 随机. 实测 **0.051**  这条同时证明了 BPM 与相位都对. 超过 0.30 说明 BPM 测错或相位没对齐, 卡点层会整体偏掉, 不要往下做

## 与 `07-grid` 的区别(别混)

`07-grid` 的 `grid.json` 是**给人声音拍吸附用**的(纠正 CTC 的挤压). 这里的事件表是**给卡点层当触发源**用的. 两者都基于伴奏, 但服务对象完全不同  前者服务"字什么时候唱", 后者服务"环境什么时候炸"
