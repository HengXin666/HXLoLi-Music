# 42 主文本层设计

## 只做这一件事

产出一张**逐句设计表**: 每一句的日文主唱行, 在**五个生命阶段**上各做什么. 写完它, `49-generate` 基本就是"把表翻译成代码"

**动手前先重读 `proj/song-brief.md`**(见 `shared/hard-rules.md` 第 4b 条)  尤其「歌曲在番剧背景下的分析」那一节. 母题列能不能指到它, 决定这一句是在做**这首番**的歌, 还是在做**任何一首**歌

## 五个生命阶段(本步的维度)

| 阶段 | 时间粒度 | 库里现成的机制 |
|---|---|---|
| **出现** | 句首 −lead(默认 0.8s) | `o["ent"]` / `din` / `stg_in` |
| **逐字** | 该字音拍 | `highlight()`: wipe / bloom / jump / flipx / shake / ink |
| **词组关联** | 跨越 2 字以上 | `seq()/find()/span()/mid()` |
| **意象** | 该词的音拍 | 主母题图形(元素表条目) |
| **消失** | 句尾 + hold | `o["ext"]` / `dout` / `stg_out` |

**五档都能指到库里已有的机制**, 不是新造的概念. 旧表只填了 3 格(入/出/高亮各 1 列)

## 设计表的每句一行

列名与判据见 `impl/design-table.md`(机器读的, 不许改). 主文本那五列

```
| 句 | 时间窗 | 主·出现 | 主·逐字 | 主·词组 | 主·意象 | 主·消失 | ... |
| 愛のイロハを学んでも | 25.9–29.0 | rise 25ms | 「愛」bloom / 其余 wipe | イロハ:片假名飘成平假名 | 心形脉冲·A(愛) | rise ↑20px | ... |
```

**母题列必须能指到 `anime.notes.md` 的某一行 + `anime.elements.md` 的某个条目**; 指不到的句子要显式标「氛围句」, 且**氛围句占比 ≤35%**. 每格**要么填要么写 `—`(决定不做)**, 不许留空

## 四件必须做的事

1. **抽帧写镜头时间线**(每 1.5s: 时间 → 画面内容 → 主色调 → 亮/暗). 抽帧的用途是**读镜头**(配色、构图、亮暗), 不是去抄画面里的字
2. **特效时间点尽量对齐镜头切换**, 而不是只对齐歌词
3. **一句 = 1 意境 + 1 主母题 + ≤3 辅助母题**  这是**格子内部**的层级, 与五阶段正交, 有先后: 先选阶段, 再决定该格子里叠几层
4. **依据是"词义", 不是"图形菜单"**: 函数名要像 `fx_grasp` / `fx_birth`, 不能像 `fx_petals` / `fx_dust`  后者换任何歌都能用, 等于什么都没说

## 核心手法: 把句子的语法结构变成动画的时间结构

三个参考工程最关键的共性. 以 `fx_grasp`(「手に入れられない」= 抓不住)为例

```python
te = find(ph, "手")[0]
t_break = nai[0]["s"]          # 「ない」= 语义反转点
for i in range(10):            # 10 道夕光汇聚到「手」
    f.shape(7, t0, te["s"]+0.45, x0, y0, te["x"], JY-6, ...)
f.shape(6, t_break, t_break+0.9, ...)   # 光球从指间滑落
f.burst(t_break+0.35, ...)              # 碎开
```

判据
- 这段动画的**转折时刻**是否落在某个**词**上?
- 把图形单独拿出来, 不看歌词, 能不能猜到它在说什么?

## 尺寸约束

band **只有 758×242**(1080p, 歌词块外扩 5%): 单个图形 **30~70px**, 精细图形(网络 SVG 的 3000+ 字符路径)缩到 40~70px 用. 要"铺满"靠 **`drift` + `burst` 的数量**, 不靠单个图形的大小. **背景层也只在这个 band 内**(见 `45-bg`)
