# 特效层次: 文本对象 × 生命周期(两个正交轴)

> 决策与实测依据: [2026-10-03-karaoke-design-15-cells.md](../../../../notes/implemented/process/2026-10-03-karaoke-design-15-cells.md)

`impl/three-layers.md` 只回答了"同一处图形叠几层"(意境/主母题/辅助母题). 它漏了一个更基本的维度:
**特效挂在哪个文本对象上, 以及挂在那个对象的哪个生命阶段**. 两者正交 —— 缺一个, 设计空间就少一半.

## 一、轴 A: 文本对象(谁在动)

| 对象 | 内容 | 样式 | 谁在唱 |
|---|---|---|---|
| **主文本** | 日文歌词行 | `JP` / `LAT` | 主唱 |
| **副文本** | 振假名 / 中文 / 合いの手 | `RB` / `CN` / call | 注音跟随汉字; 中文不发声; call 是伴唱 |
| **背景** | 不属于任何一个字 | `FX`, layer 0~1 | —— |

**判据**: 每条 fx 事件都要能说出它服务上面哪一行文本. 说不出的 = 无主装饰, 删掉.

## 二、轴 B: 生命阶段(什么时候、什么范围)

五档, 由内到外:

| 档 | 时间粒度 | 范围 | 库里现成的机制 |
|---|---|---|---|
| **出现** | 句首 −lead(默认 0.8s) | 整句 | `o["ent"]` / `din` / `stg_in` |
| **逐字** | 该字音拍 | 1 字 | `highlight()`: wipe / bloom / jump / flipx / shake / ink |
| **词组关联** | 跨越 2 字以上 | 词、词组 | `seq()/find()/span()/mid()` + `line.py` / `thread.py` |
| **意象** | 该词的音拍 | 词 | 主母题图形(元素表里的条目) |
| **消失** | 句尾 + hold | 整句 | `o["ext"]` / `dout` / `stg_out` |

五档 × 三个对象 = **15 个格子**. 现在的设计表只填了约 3 格(主文本的意象与逐字、背景的意境).

## 三、15 格清单与现状

| 格 | 库里有没有 | 设计表有没有 | 现状 |
|---|---|---|---|
| 主文本·出现 | 有(`ent`, 9 种) | 有 1 列 | 全曲被填成同一个值 |
| 主文本·消失 | 有(`ext`, 7 种) | 同上 1 列 | 同上 |
| 主文本·逐字 | 有(`hl`, 6 种, 可逐字 `hl_kind`) | 有 1 列 | 基本只用 `wipe`/`bloom` |
| 主文本·词组关联 | **部分**: `line.py`/`thread.py` 只在被否工程里用过 | **没有** | 设计表没有这一列, 于是没人做 |
| 主文本·意象 | 有(`props.py` 41 件 + 主母题) | 有 | 做得最多的一格 |
| 副文本·出现 | 有(`rb_ent` / `cn_ent` / `cn_delay`) | **没有** | 33 句全走默认, 永远"注音晚 0.06s、中文晚 0.2s" |
| 副文本·消失 | 有(`stg_out` 共用) | **没有** | 同上 |
| 副文本·逐字 | 有(注音逐字事件 `r["s"]`) | **没有** | 注音一直是"跟着汉字整块淡入" |
| 副文本·词组关联 | 有(注音 ↔ 汉字的 `host` 绑定) | **没有** | 未用 |
| 副文本·意象 | 无 | 无 | 副文本不带意象, 这是对的 |
| 背景·出现/消失 | 有(`mood_bg`) | 有 1 列(意境) | 只有 10 种通用氛围 |
| 背景·逐字 | 无 | 无 | —— |
| 背景·场景 | **无** | **没有** | 背景层不读 MV 画面 |
| 背景·情感 | 无 | **没有** | 背景层不读段落情绪 |
| 背景·番剧特征 | **无** | 没有 | 番剧符号只走主母题的意象 |

**这张表就是"忽略了什么"的答案**: 副文本 5 格里 4 格是空的, 背景 4 格里 3 格是空的, 词组关联那一格是空的.

## 四、副文本为什么必须单独设计

`anim.py` 里注音与中文**各有独立旋钮**(`rb_ent` 注音入场 / `cn_ent` 中文入场 / `cn_delay` 中文延迟),
注音还有自己的逐字事件(`for r in ph.rb: ... doc.ev(3, r["s"], ...)`).

但设计表里一列都没有 → 33 句全走默认值 → 注音永远比主字晚 0.06s、中文永远晚 0.2s.
**用户看到的"一句里所有东西一起动"就是这个原因**: 三个对象共用一条时间曲线.

修法: 设计表为副文本单列两格 —— **出现**(比主文本早/同步/晚, 差值写秒)与**逐字**(注音是否逐拍点亮).
中文不是唱的, 它的出现应该跟着**语义单元**(整句译完)而不是跟着主唱音拍.

## 五、背景层: 不是全屏, 是"画面在字幕带上的折射"

band 铁律不变(`shared/hard-rules.md` 第 5 条), 所以背景层**只能**在 band 内.
专业参考也是这么做的: 实测东方 `orig_ref.ass` 的 42872 条事件全部落在 y 856~972 的一条横带里,
Ptcl / Flow / Faith 三个背景样式的 x 范围 372~1392 —— 没有一条铺到画面中部.

所以背景层 = **由该秒 MV 画面 + 该段情绪 + 番剧符号三者驱动的一层**, 在 band 内用数量、色温、运动方向表现.
它与 `mood_bg`(10 种通用氛围)的区别就是驱动源: 后者只读歌词, 前者要读镜头时间线.

**判据(可机械查)**: 背景层事件的**数量与色温**在同一时刻必须与该秒抽帧的主色/亮暗相关
(镜头时间线 `review/scene_timeline.md` 里有记录). 查法: 按句取背景层事件的 `\1c` 色温均值,
与该句覆盖镜头的抽帧主色做符号比对 —— 同号才算"背景跟了画面".

## 六、与 `three-layers.md` 的关系

`three-layers.md` 讲的"意境背景 / 主母题 / 辅助母题"是**图形层级** —— 它是本文轴 A "主文本"那一列的**内部**结构.
两者不冲突, 有先后: **先选对象与阶段(本文), 再决定该格子里图形叠几层(three-layers.md)**.

## 七、写设计表前先过一遍

1. 这句的主文本, 出现/消失各是什么? (不是每句都 fade)
2. 这句里有没有一个**词组**值得做关联特效(两个字的距离、顺序、连接)? 指到具体哪几个字.
3. 副文本(注音/中文)的出现时刻, 与主文本的关系是什么? **不许留空, 不许全曲同值**.
4. 这句的背景层, 对应哪个镜头的哪一秒? 那一秒的画面主色是什么?
5. 五个档里, 这句放弃了哪几档? **放弃了要写出来** —— 不做和忘了做, 结果一样但原因不同.
