# 逐句设计: 从词义到图形(读三个参考工程得出)

本文是 `impl/motif-catalog.md` §2 的**判据细化**. 依据是三个已完成工程的实际做法
(無職転生 ED1「オンリー」/ ヨスガノソラ OP「比翼の羽根」/ ED「ピンクジョーンズ」),
合计 **126 个特效函数、131 条逐句设计**, 逐条记录.

## 1. 铁律: 一个句子 = 一个专属函数

三个工程的统计:

| 工程 | 特效函数 | 逐句条目 | 带画面注释的条目 |
|---|---|---|---|
| 無職転生 ED1 | 33 | 33 | 33(100%)|
| ヨスガノソラ OP | 42 | 45 | 45(100%)|
| ヨスガノソラ ED | 52 | 56 | 56(100%)|

**函数名就是那句词义的具象化**, 不是"意境":

    fx_birth          婴儿的小脚、小手握住手指(诞生)
    fx_grasp          夕阳下交握的手 → 「手に入れられない」拿不到
    fx_campfire       篝火
    fx_autumn         瑞杰路德·红叶悬崖
    fx_promise        拉钩约定
    fx_break_red      艾莉丝战斗
    fx_sylphie_tree   希露菲在大树下
    fx_sword_heal     保罗持剑 / 塞妮丝治愈魔法
    fx_break_wheat    麦田夕阳
    fx_dinner_flip    一家人的晚餐
    fx_only_you       洛琪希微笑(收束)

**禁止**: `fx_petals`、`fx_dust`、`fx_glow_curtain` 这类"从图形菜单里挑"的名字.
它们的共同问题是**与这首歌无关**——换到任何一首歌都能用, 也就等于什么都没说.

## 2. 依据必须写进注释: 画面时间点 + 内容

三个工程 **131/131 条**都有形如这样的注释:

    # 19.5-28.5 婴儿的小脚、小手握住手指(诞生)
    # 30 夕阳下交握的手
    # 31.5 篝火 / 33 骑蜥蜴 / 36 雾
    # 90 保罗持剑 / 91.5 塞妮丝治愈魔法

一条注释常常对应**多个**画面点(OP 有 24/45 条这样). 这意味着:
**设计前必须做完 `review/scene_timeline.md`**, 且每句都要能指出它对齐了哪几秒的画面.

## 3. 核心手法: 把句子的语法结构变成动画的时间结构

这是三个工程最关键的共性. 以 `fx_grasp` 为例(「手に入れられない」= 抓不住):

    te = find(ph, "手")[0]          # 定位「手」这个字
    t_break = nai[0]["s"]           # 定位「ない」——语义反转点

    for i in range(10):             # 10 道夕光从画面边缘汇聚到「手」字
        f.shape(7, t0, te["s"]+0.45, x0, y0, te["x"], JY-6, ...)

    # 「拿不到」—— 光球从指间滑落、碎开
    f.shape(6, t_break, t_break+0.9, cx, JY-4, cx+30, f.b[3]-30, ...)   # 滑落
    f.burst(t_break+0.35, ...)                                          # 碎开

**不是装饰, 是把句子读懂了再用图形复现. ** 判据:
- 这段动画的**转折时刻**是否落在某个**词**上? (这里是「ない」)
- 把那段图形单独拿出来, 不看歌词, 能不能猜到它在说什么?

对照 `fx_birth`(「愛のイロハを学んでも」):

    for c in seq(ph, "イロハ"):     # 「イロハ」= 入门、ABC
        g = {"イ":"い","ロ":"ろ","ハ":"は"}[c["ch"]]
        f.text(6, c["s"], c["s"]+1.2, ..., g, ...)   # 片假名飘成平假名

**「イロハ」这个词本身就被画了出来**——不是画个爱心就算"爱".

## 4. 手法用量(三工程合计, 可直接参考)

| 调用 | 次数 | 用途 |
|---|---|---|
| `f.shape()` | 209 | 全部绘图(最多, 是主体)|
| `\t(` 链 | 160 | 形变链(延续动感)|
| `f.seq()` | 145 | **按词定位**(几乎与 shape 同量级——词级定位是常态)|
| `f.pulse()` | 58 | 脉冲 |
| `f.find()` | 45 | 定位单字 |
| `sway()` | 44 | 摇摆 |
| `f.glow()` | 42 | 辉光 |
| `f.burst()` | 40 | 迸发 |
| `f.drift()` | 26 | 飘落 |
| `f.text()` | 12 | 文字型特效 |
| `\org` | 12 | 旋转原点 |
| `flicker()` | 11 | 闪烁 |
| `f.floor_spin()` | 3 | 地面法阵 |

**注意 `seq()` 的用量**: 145 次, 和 `shape()` 同一量级.
说明**大多数特效是挂在"词"上的, 不是挂在"整句"上**.
用 `find(ph, "手")` / `seq(ph, "ない")` 把图形精确挂到某个字或某几个字.

## 5. 检查清单(写每一句之前先过一遍)

1. 这句对应的**画面**是哪几秒? 写进注释.
2. 这句里有哪个**词**是"可以被画出来的"? (名词/动词优先, 抽象词次之)
3. 句子的**结构**是什么? (否定/转折/递进/重复)→ 动画的结构应该跟着它.
4. 把图形单拿出来, **不看歌词能不能猜到含义**? 猜不到就重做.
5. 特效只占 band, 且**不超过歌词本身的视觉重量**(参考工程的 glitch 类都压得很低).

## 6. 反面清单(我在 tsunagu 工程里犯过的错)

| 错误 | 后果 |
|---|---|
| 用 `fx_petals`/`fx_dust` 这类通用图形 | 与歌无关, 换任何歌都能用 = 什么都没说 |
| 从"意境表"里挑(花瓣/尘埃/光幕)| 用户原话「这根本就不是这个剧情的重点」「屁用没有」|
| 特效比画面主体还大 | 盖住人物的脸, 喧宾夺主 |
| 只对齐歌词时间, 不对齐画面 | 「跟整体的番剧以及 MV 的画面完全就是零关系」|
| 一条线从 36 句套同一个模板 | 「禁止偷懒, 禁止套模板」|
## 7. 密度配方(三工程实测的通用配方, 照抄即可)

`fx_flowers` 是最典型的模板, **三段式**:

```python
def fx_flowers(f, ph, k):
    R = f.rng
    cols = ["#FF5AAE", "#FF8AC8", "#FFE04A", "#FFFFFF", "#FFB0D8"]
    # ① 环境层：drift 铺 30 颗（不是 10 颗！）
    f.drift(k.t_in, k.t_end, 30, cols, lambda s: S.sakura(s) if R.random() < 0.5 else S.petal(s),
            vx=(15, 50), vy=(-12, 12), size=(6, 10), a=(10, 90), blur=(0.5, 1.2))
    # ② 逐字层：每个字 2 颗，带自转
    for c in ph.chars:
        f.burst(c["s"], c["x"], JY - 10, 2, cols, draw_fn=S.petal,
                speed=(30, 70), up=0.6, size=(4, 6), spin=True)
    # ③ 关键词层：定位到词，挂一个大图形，从小弹到满
    for key, cc in (("ため？", "#FF5AAE"), ("自分", "#FFE04A")):
        chs = seq(ph, key)
        if chs:
            t = chs[-1]["s"]; x = chs[-1]["x"] if key == "ため？" else mid(chs)
            f.shape(0, t, k.t_out + 0.3, x, JY, draw=S.flower(56), c1=cc,
                    a_peak=130, blur=2, fade_in=0.2, fade_out=0.4,
                    extra="\\fscx10\\fscy10\\frz-60\\t(0,600,0.5,\\fscx100\\fscy100\\frz0)")
```

**我犯过的错是把顺序反了**: 只画 ③ 那个大图形, 没有 ①② 的基础密度.
结果就是"一个大东西挂在那, 周围空空的"——用户说"丑"、"屁用没有".

**先铺量, 再点睛. ** ①② 给了 30 + 2×字数 ≈ 45 颗的底, ③ 才显得是"点睛"而不是"孤零零".

## 7b. 形态纪律: 图形要**轮转**, 不是同一个刷 N 遍

`§7` 的三段式配方里, ①环境层 ②逐字层 ③关键词层**必须用不同图形**.

实测失败模式(2026-10-03, 漆黑子弹 v5 第一版): `amb` / `hold` / `per_char` 三处都用
**同一个** `draw` 参数刷数量 —— 单帧 49 条绘图事件里 **33 条是同一形态**,
33 句在形态上完全同质. 观众读到的是"每句都在同一个位置浮同一片光点", 颜色再分化也救不回来.

修法: 图形按"每 3 颗换一种"轮转. 两条硬要求:

1. **轮转表里的名字必须真实存在于 `assets/shapes.json`** —— 写不存在的名字会**静默回退**
   成默认图形, 看起来"轮转生效了"却没有产生任何多样性(实测踩过).
   写之前先 `hx-karaoke python -c "import json;print(sorted(json.load(open('proj/assets/shapes.json'))))"`.
2. **量形态多样性必须用完整路径 md5**, 不能用路径前缀.
   实测: 用前 26 字符当指纹会得出"每句只有 2 种形态"的**错误结论**(大多数多边形前 26 字符一样);
   换完整 md5 才是真值(v4 中位 4 → v5 修前 2 → 修后 **11**).

## 8. 尺寸的硬约束: band 只有 758×242

实测字幕 band = `758×242`(1080p, 歌词块外扩 5%). 这意味着:

- **单个图形不要超过 ~200px**, 否则被 `FX.shape()` 夹取(`clamp` 计数飙升)
- 参考工程的图形尺寸: `flower(56)` / `heart(62)` / `sparkle(30)` / `sakura(s)` 配 `size=(6,10)`
  —— **都在 30~70px 量级**, 不是 200px+
- 想要"铺满画面"的效果, 靠 **`drift` + `burst` 的数量**, 不是靠单个图形的大小

我在 tsunagu 里画过一个占据画面 1/3 的心形结, 不但被夹取, 还盖住了人物的脸. **这是明确的反面教材. **
## 9. 铁律复述: band 内, 没有例外

第 8 条硬规则是**永久强制**的: 特效只能落在字幕 band(歌词包围盒外扩 5%, 实测 758×242).
**任何跑出 band 的内容都是垃圾, 一律不许交. **

以下做法我试过、全被否掉, **不要再试**:

- ❌ 特效当"画面背景层", 登记整幅 band(`FULL_BAND`)
- ❌ 丝带铺满画面 / 巨型图形占画面 1/3
- ❌ "字幕左右两侧的垂落边框"(那也在 band 外)
- ❌ "画面中部更空所以放那里更清楚"

**band 只有 758×242, 所以图形必须小、必须多. ** 这不是限制, 是判据 ——
它让整片字幕退化成固定矩形, 裁剪是常数、不需要 K 帧跟随(实测逐帧裁剪会让缩放漂移 56.6%).

在这个尺寸下的正确做法:

- 单个图形 **30~70px**(参考工程实测值: `flower(56)` / `heart(62)` / `sparkle(30)`)
- 密度靠 **数量**: `drift` 26~30 颗 + 逐字 `burst` 2 颗 —— 约 45 颗的底
- 精细图形(网络 SVG 转出的 3000+ 字符路径)要**缩到 40~70px** 用, 靠形状本身取胜, 不靠尺寸
