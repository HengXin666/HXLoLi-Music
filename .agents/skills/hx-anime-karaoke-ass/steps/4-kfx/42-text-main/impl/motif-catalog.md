# 特效设计方法

## 1. 三层理解: 先读懂再动手

**第 1 层必须先产出文件**: 先查同番工程有没有做过(有就必读), 再跑 `scripts/source/fetch_anime_bg.py` 抓 bgm.tv 条目与角色简介,
读萌娘百科正文, **并做六类检索**(考察文 / 官方访谈 / 改编差异 / 题名考据 / 舞台原型 / 乐谱转调). 写成 `proj/anime.notes.md`: 四个必答问题(内核、主题、与原作的关系、情绪曲线)+「角色 → 视觉母题 → 图形库对应」表. 做法与判据见 `steps/3-anime-bg/10-anime-bg/impl/background-research.md`. **只凭自动搜索 + MV 画面下结论是不合格的**  那样每句只能画通用心形/星星, 靠换配色撑整首
**番剧歌是原作的隐喻**: MV 画面只说"这一段在放什么", 原作内涵才决定"这一段该是什么情绪"(亮/暗、暖/冷).
下面这段是"读了设定之后长什么样"的例子, 不是可以跳过第 1 层直接抄的模板

1. **番剧背景**: 主角经历、关键人物的符号(例: 师父=魔女帽/水魔法, 剑士=红发/剑, 战士=额上宝石/守护, 治疗师=治愈魔法; 主题「第二次的人生、这次要认真活」)
2. **歌曲意图**: 主旨与情绪曲线(例: 曲名 = 对「唯一的你」的告白; A 段温柔回忆 → 副歌「想要破坏/想要守护」的矛盾激情 → 结尾收束)
3. **MV 镜头**: 每 1.5s 抽帧写**镜头时间线**(时间 → 画面内容 → 主色调 → 亮/暗). 特效时间点尽量**对齐镜头切换**而不是只对齐歌词

## 2. 设计表(每句一行)

「母题/图形」列必须能指到 `anime.notes.md` 的某一行; 指不到的句子要在该行显式标注「氛围句」

| 句 | 时间窗 | 画面(时间点) | 意境背景 | 主母题 | 辅助母题(≤3, 各挂一个词) | 配色(hi/glow/dark) | 入/出/高亮 | 触发点 |
|----|-------|-------------|---------|-------|--------------------------|-------------------|-----------|-------|
| 愛のイロハを学んでも | 25.9–29.0 | 婴儿小手握手指(19.5–28.5) | 暖光垂帘+微尘上浮 | 心形脉冲(愛) | 小爱心(イロハ)／飘字(学) | 桃色暖光 | rise/rise/bloom | 「愛」出心、每字爱心 |
| 壊したい… | 51–57 | 战斗(55.5) | 暗红雾+火星上升 | 裂纹碎裂(壊) | 刀光(貴方)／碎片下落(想) | 白/红 | zoom/scatter/shake | 每个「壊」、「貴方」刀光 |
| 守りたい… | 63.7–69.2 | 蓝色魔力球(64.5) | 地面法阵辉光+尘埃 | 符文环(守) | 光球升起(全て)／水纹(想い) | 蓝 | rise/rise/bloom | 「守」脉冲、「全て」光球升起 |

原则
- **一句 = 1 个意境背景 + 1 个主母题 + 最多 3 个辅助母题**
  - **意境背景**: 铺满整句时长的氛围层(飘落/辉光/尘埃/水纹/雾), **每句都必须有**
    它不带叙事、只给质感  没有它就"平", 有了它才有"空气感".
  - **主母题**: 这句的情绪核心, 规模最大、挂在该句情感最重的词上
  - **辅助母题**: **按词分组**, 一句里挑 2~3 个不同的关键词各挂一个**不同**母题
    关键是"不同"三个都用心形只是数量堆叠, 观众读不出层次.
    例: 「錆びて消えない孤独の寂しさを」→ 錆=锈蚀纹理 / 孤独=下坠碎片 / 寂しさ=涟漪扩散.
  - **判定**: 一句里 fx 事件按 band 分组, **不同图形种类 ≥ 6**(不是同一图形叠 6 次)
    判据与实测阈值见 `impl/density.md`.
- **同类句(每次副歌)换配色/材质**以呼应当时画面(红→金麦→水), 但母题骨架可复用
- **触发点=音拍**: 大特效挂在关键字的音拍起点上(`c["s"]`), 环境类(飘落/余烬)用 `drift` 铺满句子时长
- **画面优先**: 画面已经很满(爆炸/花田)时特效要克制; 画面空(天空/黑场/遮幅)时可以多给
- **可读性优先**: 特效放 Layer 0(字后)时 alpha 高一些(150~210), 放字前(Layer 5~8)时尺寸小、时长短
- 亮场(雪/白墙/花田)开 `bright=True` 加重阴影

## 4. 动画语汇(`anim.py` / ASS 标签)

- 入场: 温柔句 rise/fade; 激烈句 zoom/glitch; 回忆句 slide; "翻转/另一面"用 flipx
- 退场: 风(wind)、上升消散(rise)、下沉(sink)、碎裂(scatter). 位移 ≤80px/30px, 保证不出 band
- 高亮: wipe(标准)、bloom(温柔/光)、jump(跳动/背伸び)、shake(破坏)、ink(晕染/失去)、flipx(翻面)
- 逐字错落 20~35ms; 长音(>0.8s)自动加呼吸光晕
- 连唱衔接: 由生成器自动缩短退场, 别手动叠两句

## 4b. 两种风格的对照(抒情 vs 电波)

| | 抒情路线(OP) | 偶像/电波路线(ED) |
|---|---|---|
| 意图 | 成对意象(必须并肩才成立); 夏日乡间与离别 | 冒险·运动会·吃货·根性的元气大杂烩; 成员名彩蛋 |
| 字体 | 明朝 + 文楷, 细描边 | Mochiy Pop One + 站酷快乐体, 粗描边、纸片剪贴阴影 |
| 母题 | 成对羽翼、两颗并排光点、云、列车、单车、小提琴 | 漫画爆炸框、彩旗、奖牌、香料、心跳、门、星星、彩纸屑 |
| 入场/高亮 | fade/rise/slide + bloom/wipe/ink | drop/jump/spin/shake + 爆炸框"拟声字" |
| 彩蛋 | 两位主角名各一颗光点, 相遇成翼 | 成员名句: 成员色高亮 + 名牌 tag |

- **歌词里藏的梗要找出来**: 成员名、双关、引用(某句古诗/名句), 设计成专门的高亮
- **呼喊/合いの手**用和主歌词不同的视觉语言(爆炸框、小号字), 在 band 内错开位置弹出
- 同一首歌的副歌多次出现时, 特效骨架相同、细节随画面变化(配色/道具), 观众能认出"又是这句"

## 5. 卡片: 只做【开头】与【片尾】两张

利用黑场与长前奏/尾奏做卡片, **只允许两张**

| 位置 | 内容 | 例子 |
|---|---|---|
| 开头(前奏黑场) | 曲名 + 番剧名 + 制作名单 | 曲名 / アーティスト / 挿入歌·番剧名 |
| 片尾(尾奏黑场) | 制作署名 | 作詞・作曲・編曲 …… ／ 字幕制作: …… |

**除这两张之外, 不要在歌词之间插任何文字. ** 尤其是「间奏卡」「序章卡」这类 哪怕写的是番剧主题、点题句、词源考据, 本质都是**在歌词停顿时塞入观众没在听的旁白**, 观感是"画蛇添足", 而且极易与相邻歌词行的时间窗互撞(实测一例撞出 6.8s 重叠). 番剧考据与母题的产物**不是卡片**, 是 `anime.notes.md` 与每句的特效设计

**制作名单照实写**: 谁做的曲子写谁, AI 生成方写模型名与发起人(如
`作詞・作曲 <作者名> ／ 特效与字幕: <模型名> × <用户名>`). 不要编造工作室名

卡片同样登记 band(文字墨迹外扩 5%), 特效只在卡片周围. 用 `Generator.card()`: items 的 Metric 必须对应样式字体, 样式 Spacing 自动计入宽度. 卡片**允许是纯文字**(不放特效), 不要为了"热闹"在卡片上堆图形
