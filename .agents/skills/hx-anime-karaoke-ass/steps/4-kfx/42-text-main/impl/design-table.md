# 设计表: 15 格怎么落成一张表

> 决策与实测依据: [2026-10-03-karaoke-design-15-cells.md](../../../../notes/implemented/process/2026-10-03-karaoke-design-15-cells.md)

`impl/layers.md` 定义了 3 个文本对象 × 5 个生命阶段 = 15 格. 本文给出**表形态 + 填写规则 + 机械判据**

## 一、表形态(列名是机器读的, 这几个词不能改)

```
| # | 句 | 时间窗 | 主·出现 | 主·逐字 | 主·词组 | 主·意象 | 主·消失 | 副·出现 | 副·逐字 | 副·消失 | 中·词对应 | 背景·场景 | 背景·情绪 | 背景·番剧 | 承上 | 启下 |
```

15 个阶段列 + 3 个定位列 + **`中·词对应` 一列**. **每句一行**, 与旧表一样  没有变细颗粒, 变的是**列的维度**: 旧表把"入/出/高亮"塞成 1 列(3 格), 新表是 15 格

`中·词对应` 是**中文行的驱动数据**, 不是描述. 格式见 §七. 它必须与 `副·出现` 分开写  前者是**词级对应关系**, 后者是**整层的时间参数**

## 二、每格的填写格式

| 列 | 填什么 | 例 | 禁止 |
|---|---|---|---|
| 主·出现 | 入场类型 + 逐字错落(ms) | `rise 30ms` | 全曲同值 |
| 主·逐字 | 高亮类型(可逐字变) | `wipe` / `「壊」shake` | 全曲只写 `wipe` |
| 主·词组 | `词:图形@挂点` | `イロハ:飘字@逐字→平假名` | 空着(→ 记为放弃, 见 §四) |
| 主·意象 | 元素表条目 + 级别 | `红眼·A` | 通用图形名(心/星/花瓣) |
| 主·消失 | 退场类型 + 位移 | `scatter ↓20px` | 全曲同值 |
| 副·出现 | 注音/中文各自相对主文本的**秒差** | `RB +0.06s / CN +0.20s` | 全曲同值 |
| 副·逐字 | 注音是否逐拍点亮 | `RB 逐拍` / `RB 整块` | 空着 |
| 副·消失 | 注音/中文退场与主文本的先后 | `RB 同步 / CN 晚 0.3s` | 空着 |
| 中·词对应 | **中文每个词由哪个日文词驱动**(见 §七) | `L1 3-4→1-2 同色` / `L3 [(0-2)(3-5)]` | 空着(除非整句中文不做) |
| 背景·场景 | 该秒 MV 画面(抽帧时间点) | 画面内容 + 时间点 | 空着 |
| 背景·情绪 | 该段在情绪曲线上的位置 | `A段·压抑` | 空着 |
| 背景·番剧 | 该元素在 band 内的形态 | `红眼虹膜环·缩到 40px` | 越出 band 的任何描述 |
| 承上 | 从上一句带过来的**变量** | `色相 +15°` / `末位置 x=640` | "延续上一句的感觉" |
| 启下 | 留给下一句的**变量** | `留一条向右的动量` | 同上 |

## 三、承上 / 启下 必须是"变量", 不是"感觉"

五种可核对的承接类型见 `impl/thread.md` §二. 写"有承接感"无法证伪, 等于没写

**一条硬规则**: 承上列的变量, 必须能在上一行的启下列里找到**同名**的那一项.
两行对不上 = 表自己都说不通. (机器只查"两列都非空 + 变量名有交集", 语义由人读.)

## 四、空着的格子要显式写"放弃", 不许留白

五个档里必然有些句子用不上(短句没有词组、纯器乐句没有人声). **留白 = 忘了做, `—` = 决定不做.** 两者的区别是这一列存在的意义. 判据: 每行的 15 格里, 空串数量为 0(要么填, 要么写 `—`)

## 六、一个填好的例

**不许去翻任何历史工程的表**(见 `shared/hard-rules.md` 第 10 条). 每格怎么填, 判据在 §二/§三/§四/§七; 机械阈值在 §八

**禁止把 §二 的"例"栏当成可抄的答案.** 那些格子写的是**格式**, 不是**内容**; 内容必须从这首歌的 `song-brief.md` 与 `anime.elements.md` 推出来. 照抄格式是合格, 照抄内容就是拼贴

## 七、`中·词对应`: 中文行怎么被驱动(三层)

**前提**(见 `shared/hard-rules.md` 第 6d 条): 中日语序不同, **中文永远不按字高亮**. 中文的视觉只能由"它对应日文哪个词"决定

三层, 从弱到强. 每句选一层并写出**可核对的数据**:

| 层 | 写什么 | 判据 |
|---|---|---|
| **L1 颜色对应** | `L1 <日文词序> → <中文词序> 同色` | 两侧下标必须在各自句子的词数范围内; 每个 `日文词` 至少被一个中文词对应一次(允许多对一) |
| **L2 特效同步** | `L2 <日文词序> 的 <特效名> → 中文 <词序> 同步` | 该日文词必须在 `主·词组`/`主·意象` 里真的挂了特效, 否则这条是空的 |
| **L3 整句按序** | `L3 [(词序段)(词序段)...]` | 段数 ≥2 且覆盖全部中文词, 相邻段不重叠 |

**三条硬纪律**

1. **词对齐写不出来就不许猜.** 退到 L3, 或整句中文只上色不做动. 猜出来的对应关系会让观众更迷惑
2. **中文自己不许另想特效.** L2 是**复用日文那次触发**(同一特效类型、同一时刻), 只把作用对象换成中文对应词. 中文层可以**完全没有特效**(只 L1)
3. **L3 不跟音拍.** 它是"意群顺序", 与日文唱到哪无关  这正是用来绕开语序错位的

## 八、机械判据(`scripts/gate/check_gates.py`)

```bash
hx-karaoke check_gates.py --project proj --stage design
```

| 判据 | 阈值 | 为什么 |
|---|---|---|
| 列数齐全(17 列)、每行无空串 | 全部 | 列名被正则钉死; 空串 = 没做也没声明 |
| 行数 == `lyrics.txt` 的正词行数 | 相等 | 漏句在成片里只是一段空白, 其它门禁全过 |
| `主·逐字` 的不同取值数 | **≥3** | 全是 `wipe` = 全曲一套动效 |
| `副·出现` 的不同取值数 | **≥3** | 全是 `+0.06s/+0.20s` = 副文本从没被设计过 |
| `副·逐字` 非 `—` 的行占比 | **≥0.5** | 注音逐字点亮是专业作品的标配 |
| `中·词对应` 非 `—` 的行占比 | **≥0.6** | 中文不做逐字, 若连词对应也不写, 这一层就是纯背景字 |
| 同句里 L1/L2/L3 **不许混用**(只能选一层) | 全部 | 混用 = 没想清楚哪层在做主 |
| `承上` 与上一行 `启下` 有变量名交集的行占比 | **≥0.6** | 句间关联的机械形式 |
| `主·词组` 非 `—` 的行占比 | **≥0.4** | 词组级关联是 `impl/per-line.md` §4 实测的常态(145 次 `seq()`) |
| `背景·场景` 非 `—` 的行占比 | **≥0.7** | 背景层必须由画面驱动, 不是氛围词 |

阈值与 `impl/density.md` 同源: **定在"低于它一定不合格"的位置**, 不追求"达到它一定合格"
