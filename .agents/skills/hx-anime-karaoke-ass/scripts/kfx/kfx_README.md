# kfx: 本 skill 唯一的特效生成器

一首歌 = `lyrics.txt` + `timing.json` + `design.md`. 代码里没有任何一首歌的东西.
skill 给的是方法, 不是一套固定动作: 每首歌都要自己调研, 发明出自这首歌 / 这部番的动作 (见 "换一首歌" 第 2 步). 蓝本 オンリー kfx3 v2.1 (用户认可的版本, `examples/mushoku_ed1/kfx/`) 只用来看方法和守住金样, 不是让新歌照抄它的动作组合.

## 先读: 已经踩过的坑 (每条都是用户否决过的)

1. **只有一个生成器.** 不许新写 `karaN_*.py` / `vN.py` / 新引擎. 效果不够就加一个动作 (下文), 并跑 `kfx_test.py`.
2. **改代码先过金样.** `kfx_test.py` 要求蓝本逐字节重现. 金样变了 = 用户认可的歌变了: 先给用户看, 同意后才 `--bless`.
3. **字上的动作是主体, 物象只点缀.** 每个效果都是 "我" 对字做的事 (砍, 压, 托, 握). 字外的东西只准是 `物象` (kfx_motif): 番里的东西 (茶杯, 天空鲸, 花瓣), 从 ED 画面里取, 每首挑几样, 只放在需要的那几行, 小 (物件 ≤ 70 px, 粒子 10~20 px), 不压字, 全部踩拍. (オンリー 时期用户否决过大而看不懂的物象 = 红光球; 2026-11-23 用户又要求: "不止应该有这个洞, 还要有粒子特效 / 番剧元素的物象, 只需要一点". 两条一起守: 少, 小, 一眼认得出是番里的什么.)
4. **不越界.** 用户截取歌词区用: 任何像素都在歌词包围盒外扩 5% 内 (1080p 横 96px, 纵 54px). `kfx_check.py` K2 实渲染核对.
5. **一眼看懂.** 只粗看过番的人也要看得出是什么动作. 要细看才懂的细节不要做.
6. **禁用.** 闪烁, 旋转, 环绕, 字旁固定装饰, 盖住字的阴影或布, 穿过字的线, 字下的弧, 括号, 幕布, 火, 烧, 光当背景, 底部草石.
7. **用户给的数量是下限.** 每行至少 10 个作用在字上的动作, 至少 5 种, 每个字都要被碰到 (校验器拒绝不达标的设计稿).
8. **用户否决过的东西不恢复.** 记在工程设计稿 `## 立场` 下面或项目 note 里, 下次不要再提.
9. **不照搬上一首.** 用户 2026-11-23: "给你的是方法论, 每次应该自己去调研, 自己创新出符合这首歌的东西". 新歌的意象表至少要有 3 个这首歌才有的新动作 (出处写清: 歌词 / ED 画面 / 角色 / 官方访谈), 补丁里以它们为主; 旧动作只当配角.
10. **快歌不用两行, 用交叠 (逐字让位).** 用户否决了上下两行 (2026-11-23). 行间空隙多数 < 0.3 s 时单行轮换会让新行在开唱时才出现 (用户: "出来的时候慢了一点"): `## 全局` 写 `交叠: 0.6`, 新行每个字在自己开唱前 0.6 s 进场, 旧行站在那个位置的字提前让位; 中文行直接切换不重叠.
12. **timing.json 的 unit 要和 lyrics.txt 的记号一一对应.** kfx 按 TOKEN 逐个记号编号 (・ ！ 「 也占号, 拗音 きゃ 是两个记号). 对齐工具若按自己的分法编号 (跳过 ・, 合并 きゃ), 字会错位、整行晚出. 换歌后先核对, 不对就按读音长度重编号.
13. **卡点.** 用户 2026-11-23: "现在都流行卡点... 人会喜欢能自己预测到的、带规律的卡点". 先 `kfx_sync.py beats` 生成逐拍跟踪的 `beats.json` (固定 bpm 网格会漂, 本曲 100~140 s 漂了 0.09 s, 特效就 "不在点上"). 规则: 冲击落在拍上, 蓄力在拍前, 回弹在拍后; 小节头比其他拍重; 用可预测的规律 (左右交替, 落点从左到右轮流, 每拍一下), 看两小节就能猜到下一下. 物象和 `迸` 全部从拍网格取时间, 不写自由秒数.
14. **字慢了不要问用户, 自己量.** 用户 2026-11-23: "慢的这部分你能不能不要问我, 你自己想办法调查出来". `kfx_sync.py lag` 用人声分轨逐个 mora 找起音, 按行取中位数, 标出连续偏慢的段; `kfx_sync.py fix` 只移偏差超过阈值的行 (整行平移, 最多 0.2 s, 先备份).
15. **字序不可变.** 歌词首先是要读的. 用户 2026-11-23 否决 换位 (字互换位置): "把一个词拆了, 读着读着发现逆序了, 这吓不吓人". 动作可以跳、挤、歪, 任何时刻后一个字都不许跑到前一个字左边; kfx_build 的字序门禁逐帧查, 违反就拒绝出图.
16. **默认不放物象.** 用户 2026-11-23 先否决茶杯 (过路的) 和到处撒的心 / 花瓣 (太重复), 22:44 又否决取景框红灯、场记板、天空鲸和三色粒子: "生硬、没有动画、乱七八糟、和背景里的元素重复". 背景本来就是番的画面, 字幕再画一遍番里的东西只会撞车. 特效做在字上; `kfx_art.py scenes` 出的画面图用来理解这一句在演什么, 不是用来抄物件.
17. **高潮的 "框" 照市面上的下三分之一标题框做: 框 = 文字墨迹 + 留白.** 框是播这一句的屏幕, 唱这句时不动; 尺寸从字体文件量出的墨迹算 (kfx_ink.py, 含注音、含合成斜体), 不按字号估: 汉字在字身里留白不均, 注音只有部分行有, 估出来上下左右空得不一样, 用户一眼就别扭 (23:13). 左右留白相等、上下留白相等, 竖向 = 横向 x 0.7 (排版常用的视觉比例, 数字相等反而显得下重). 底下放不下就把这几句的中文整体下移同一距离, 不压缩留白. 动画: 开唱前一拍从中间 ease-out 展开; 换句时在新句开唱那一拍 ease-out 到新句的框 (宽高都变); 唱完第一拍 ease-in 快速淡出 (出比进快), 在下一句出现前消失; 中间: 每拍金边亮一下回落, 每小节重拍一道光沿金边扫过 (上边左到右, 下边回来) + 四角点一下头; 开场是级联 (四角弹出带一点过冲 -> 金边从中间画向两端接上四角 -> 宝石最后亮), 收尾金边缩回中间、四角收起. 留白横 46 px (23:33 用户嫌框小、动画单调不华丽). 不闪烁不旋转. M_frame 自审: 留白不均 / 唱时框动 / 压中文 / 留白被压缩 就报错. 被否决的历程: 突兀不踩拍 (22:44) -> 跟着单字伸缩 (23:08) -> 留白不均 (23:13).
11. **特效要够大.** 用户 2026-11-23 嫌新歌动作小: `## 全局` 的 `幅度` 把动作的位移 / 缩放 / 倾斜整体放大 (默认 1.0), 改完看 kfx_check K2.

## 用法

```bash
hx-karaoke kfx/kfx_build.py dev/<番>/<歌>          # 读 design.md, 写 out.kfx.ass; 设计稿不过校验退出码 2
hx-karaoke kfx/kfx_check.py dev/<番>/<歌>/out.kfx.ass --fonts <字体目录>   # K1 标签 K2 越界 K3 事件名, 失败退出码 1
hx-karaoke kfx/kfx_test.py [--full]                 # 改了 kfx_*.py 必须跑: 金样 + 校验器 + 门禁反例
hx-karaoke kfx/kfx_verbs.py --list                  # 动作表 (以代码 docstring 为准)
python3 scripts/studio/server/app.py --port 5390   # 验收台: 首页选歌 (/s/<番>/<歌>/), 改设计稿保存即重建, 监视器自动刷新; 改 kfx 代码不用重启
```

字体: 工程有 `fonts/` 用工程的, 否则用 skill 的 `fonts/` (Shippori Mincho B1 Bold, LXGW WenKai Medium, Cormorant Garamond Light).

## 换一首歌

0. 量时间: `kfx_sync.py beats <工程>` (拍网格 + 小节头) 和 `kfx_sync.py lag <工程>` (字有没有慢), 有偏就 `fix`.
1. 查立场: 作词 / 监督访谈, 是不是角色曲, "我" 是谁, 貴方 是谁. 写进 `## 立场`, 附出处. 查不到就写查不到, 不许猜.
2. 调研并发明: 看 ED / MV 画面, 歌词, 角色设定, 官方评论, 找出这首歌独有的身体动作或画面 (例: ときめき 里三人蹦跳、令嬢屈膝礼、茶会凑头聊天、魔法映像开机、尼娅出拳、片尾猜拳). 其中必须有一个**主菜**: 全曲最好看的那个点 (副歌高潮) 用一个有施动者、有冲击、看得见因果的大动作 (オンリー 的 大斩, ときめき 的 齐舞亮相). 主菜必须和那一刻的画面 / 歌词意图一致: 先看那几秒画面里人物在做什么 (ときめき 0:44 是三人跳舞, 不是打架), 用户 2026-11-23: "他们不是在跳舞吗? 有没有识别理解意图", 蹦、抖、亮 这些只是配菜, 只有配菜等于没有高潮 (用户 2026-11-23). 每个做成一个字上动作加进 `kfx_verbs_stage.py` (或新文件), docstring 写清楚, 动作表补一行, 跑 `kfx_test.py`. 再写 `## 意象` 表: 意象, 出处, 用哪个动作.
   物象: 从 ED 画面挑 2~5 样这部番一眼认得出的东西 (场景里的道具, 角色的标志物), 写进意象表. 简单的直接在 `kfx_art.py` 里画 (颜色从画面取); 复杂的从画面抠图再描: `rembg` (动漫用 isnet-anime 模型) 抠成透明 PNG -> `kfx_art.py trace <png> <工程>/art/<名>.json --h 70` (先降色再描, 层数控制在 ~100 内, 层数 = 事件数). 抠图被画框切开的边要藏起来 (例: 鲸游在云里). 不用 `\1img`: 只有定制 libass 认得, ffmpeg 预览和 kfx_check 看不到, 没人能验收.
3. 每行一节. 补丁只能用动作表里的动作.
4. `kfx_build.py` 有错就改设计稿, 直到通过; 再 `kfx_check.py`.
5. 在验收台里看, 改设计稿. 新动作和改动作都要过 `kfx_test.py` (金样不许变).

## 设计稿格式 (design.md)

```
# <歌名> 设计稿

## 立场
- 谁在唱, 唱给谁, 出处 (至少 40 字)

## 意象
| 意象 | 出处 | 动作 | 对字做什么 |
|---|---|---|---|

## 全局
- 标题: ...
- 拍: <第一拍秒> <每拍秒>        (跳 用)
- 日文字号 / 中文字号 / 行高: 可选
- 交叠: 0.35 (快歌, 新行提前进场的秒数; 默认 0)   幅度: 1.6 (动作放大倍数; 默认 1.0)
  (工程里有 beats.json 时, 拍网格以它为准; 拍 只是兜底)

## L05 · <这一行歌词, 和 lyrics.txt 一致, 空格随意>
- 色: #RRGGBB 颜色词 (为什么)
- 意境: 我对字做了什么 (意象名)
- 补丁: [词]{动作 动作·参数} [词]{...}
- 出场: 升 | 沉 | 散 | 碎 | 化
- 物象: 伴 茶杯 汽 | 洒 瓣      (可选; 见下表)
- 为什么: ...
```

物象 (kfx_motif.py, 时间全部取自拍网格):

| 物象 | 做什么 |
|---|---|
| 伴 <图> [<粒子>] | 蹲在行边 (左, 没地方就右), 每拍一弹, 小节头前半拍蓄起、落在小节头上; 每拍冒一个粒子 (小节头两个), 左右交替 |
| 游 <图> [<粒子>] | 在注音上方那条带里从右游到左, 每拍呼吸一下, 小节头喷一簇粒子 |
| 伴 <图> 右/左/定 | 定 = 不跳, 只在拍上脉动 (灯, 刻度), 居中对齐行 |
| 拍 场记板 | 行的第一个小节头 "咔" 地合上, 前一拍张开 |
| 框 魔晶板 [L<n>] | 高潮唯一物象: 数拍时一步步张开, 宽度跟当前行、在小节头到位, L<n> 唱完后下一个小节头合拢 |
| 洒 <粒子> | 每小节第 1、3 拍从上方落一个, 落点按 左-中右-中左-右 轮流 |

图: `kfx_art.py` 里画的 (录 尺 茶杯 汽 瓣 心 星 花 云) 或工程 `art/<名>.json` 描的.

只认这些字段: 色 意境 整行 每字 补丁 出场 物象 为什么. 6 字以上一行至少 3 个补丁; 每行必须有 亮; 只有 照/星/飘 的行不算数.

## 验收台前置 (新工程)

- 台子的声音只读工程里的 song.mp3 / song.flac / song.m4a, 视频轨静音. 新工程先: `ffmpeg -i base.mp4 -vn -c:a copy song.m4a`.
- 左侧歌词栏读 out.kfx.manifest.json, kfx_build 会一并写出; 只有 ASS 没有 manifest 时歌词栏为空.

18. **字体是设计的一部分, 每首歌自己选.** 全局 '日文字体' / '中文字体' 写 fonts 目录里的文件名, family 从字体文件读. 默认 (不写) = 金样用的 Shippori Mincho + LXGW WenKai, 所以 オンリー 金样不变. 抒情歌用明朝, 搞笑流行歌用圆胖字 (ろりこん 用 Mochiy Pop One + Lolita, 跟 PV 的粗圆字一致). 发布时把字体拷进 static/music/<番>/fonts.
19. **密度下限按歌定.** 全局 '每行最少动作' / '每行最少种类' (默认 10/5, 来自 オンリー 的细碎动作). 字本身就是画面的歌 (PV 是テロップ的) 要少而大的动作, 才读得清; 降低时在 立场 写为什么. 不许为了过门禁乱堆动词.
20. **テロップ动词 (kfx_verbs_pop.py): 虹 大字 警 鼓 揉.** 虹: 整行斜立 (同一条斜基线, 字序不变), 一字一戳, 虹色, 最后一声 ドン; 同一行多个词组带 虹 只斜一次. 大字: 一个词变巨大, 两边让位不重叠. 警: 字变信号红. 2026-11-23 用蓝边避开红字红边, 用户 2026-11-24 否决: "红色字加蓝色描边, 太难看, 跟个老奶奶一样"; 正解是 皮肤 贴纸 (见 21).
21. **大招要有, 而且要画出来.** 用户 2026-11-24 否决 ろりこん v1: "特效太少... 为什么不能有类似砍刀这种级别的特效? 你为什么一直以为字在跳就是特效?" 每首歌除了主菜, 每一段都要有一个画出来的大招 (オンリー 的 大斩 那个量级), 取自 PV / 歌词里的一个具体东西, 发生在字上: 集中線 冲向巨大的词, 六角カットイン 框住词, 黄黑警戒线拍在整行后再撕开, 闪电劈字, 菜刀剁 まな板, 速度线擦过, 检票章, 彩虹随戳字进度架起来, 爱心张开. 跳 / 弹 / 心跳 只是配菜. 大招全部按字 "此刻真实的位置" 画: 动词注册 late 回调 (kfx_verbs_pop `_late`), 在所有动作 / 幅度 / 出场都叠完后才读位置; 全部 clip 在 K2 允许框里 (P['box']), 大而不越界.
22. **消失要和字一起.** 同一用户 2026-11-24: "有些元素消失的时间不对劲, 没对齐, 残留在那里". 两个来源: (a) 交叠模式下旧行只有被新行压到的字提前让位, 两端的字还站着 -> 全局 `整行离场: 是`, 旧行在第一个字让位的那一刻整行一起走; (b) 画在字 "原始位置" 的东西 (余韵 的残影, 印 的章, 护 的火花) 在字被推 / 斜 / 放大后对不上, 而且活得比行久 -> 全局 `特效跟行: 是` 把每行的特效截在行结束, 并且这类旧动词在字会被移动的歌里不用, 用按真实位置画的大招.
23. **皮肤按歌选.** 全局 `皮肤: 贴纸` = telop PV 的样子: 唱过的字填行色 (或它的 tint), 外面一圈白粗边, 再一圈深色外缘; 未唱的字淡色深边. 任何彩色字都坐在白边上, 不会出现彩色字配另一种彩色边. 默认 (不写) = 金样的皮肤.
24. **timing 的 unit 先对齐再做特效.** 2026-11-24 用户: "1 分 15 秒左右对齐有问题". 原因是对齐器按 mora 写 unit (きゅ ちゃ もぉ 算一个, 「」 不占号), kfx 按记号读 (ュ ゃ ぉ 各占一个), 整行后半的字错到邻居的时间, 最后几个字没时间, 落到下一行开头. 换歌后先跑 `kfx_units.py <工程>` (只报告), 有错位就 `--write` (先备份). 再跑 `kfx_sync.py lag / fix` 修整行快慢.
25. **没有正式 MV 就不要跟 PV.** 2026-11-24 用户: "你可能要自己创一些特效, 不要去跟这个 MV 切合, 因为这个 MV 是比较古老的风格", "直接仅分析这个歌曲去做吧, 我希望有点萝莉的元素". 照搬 PV 的 六角/虹色テロップ/对白气泡 都被否. 物件从歌词里来 (被当小孩 -> 蝴蝶结 棒棒糖 牛奶), 小, 贴着词, 在音上弹出跟拍点头, 跟行走. 别人歌的动词 (映 = ときめき 的魔晶板开机) 不要顺手借: 映 把字压成一条线, 读的时候字像消失了.
26. **元素不复用, 配色不用白边黄字.** 2026-11-24 01:14 用户: "我不希望你的一些元素被复用, 希望你每次都是新的"; "黄色作为字体颜色, 白色作为描边或边框, 反正不好看"; "你到底有没有使用我的 skill? 跟之前的东西相差挺大". 做法: 画出来的东西 (物件, 大招) 全曲每个只出现一次, 设计脚本里断言; 重复的歌词各做各的; 主菜三次同一道但每次换落法/糖色/糖. 不借上一首的动作 (碰 礼 拳 蹦 映 斩). 皮肤回到 オンリー/ときめき 那套 (唱过变白 + 行色描边) 的 `跟色` 变体: 字被染色时描边与光晕跟同色系变深, 不出现白边; 物件平涂 + 同色系深细边. `物·<名>` 的图库在 kfx_verbs_pop.ICONS, 每个写明从哪句词来.
