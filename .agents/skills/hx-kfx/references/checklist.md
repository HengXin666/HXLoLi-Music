# 交付清单与门禁

## 每一步的产物与过关条件

| 步 | 产物 | 过关条件 (可判定) |
|---|---|---|
| 1 拿歌曲 | sentences.json (句 + 逐字时间) | 没有元数据行混入; 每句 t1 大于 t0 |
| 2 画面分析 | scene_analysis.py 的输出 | 读出"需底板亮度"与可选描边色, 否则不许配色 |
| 3 生成 | out.ass | 起点安全区已声明; 母题按语义挑, 不是同一个 |
| 4 逐帧测量 | measure_bbox.py 输出 | **退出码 0** (四向越界量全为 0) |
| 5 两遍收紧 | 收紧后的 out.ass | 第二遍仍退出码 0, 且常量缩放系数比第一遍大 |
| 6 门禁 | 两个门禁输出 | gradient_gate 与 contrast_check **都退出码 0** |
| 7 目视 | 抽帧图 | 至少三段各抽首/中/末帧, 逐张看过 |

**第 4 步与第 7 步不可替代. ** 门禁能验边界、种类数、点亮顺序, 验不了"绚烂"和"贴合画面"

## G-A **不是门禁**  实测在 12 份生产级成品上没有区分能力

在 12 份真实成品上跑的决定性对照

| 指标 | 生产级成品的实际分布 | 能否区分好坏 |
|---|---|---|
| 绘图几何种类数 | **2 .. 2608** (中位 6) | 不能 |
| 最高频占比 | **0.17 .. 0.96** (中位 0.71) | 不能 |
| 绘图层占比 | 0 .. 98.5% | 不能 |
| 事件密度 | 1.1 .. 291.7 /秒 | 不能 |
| 标签种类数 | 5 .. 18 | 不能 |

原来的门限"种类>=12 且 占比<=0.50"判掉了 8/12 份生产级作品 (Charlotte 只用 2 种图元、东方 6 种图元占比 0.85). **"多样性/重复度"是设计选择, 不是正确性**, 极简与极繁都能成立. 该判据已降级为仅供参考的信息输出

**这一条的方法论教训**: 任何门禁判据必须**先在一批真实成品上验证它有区分能力**,
再写进门禁. 拍脑袋定阈值会稳定地误杀好作品

本地有一份生产级成品 (来自深渊 OP) 是**零绘图 + 单手法**: 1960 事件、只有 5 种标签、4 个模板, 唯一的运动是"每个字被竖切两半、入场合拢退场张开". 它完全没有"母题多样性" 这个概念, 但成立. 所以"种类数 >= 12"会冤杀这类作品

真正该拦的是**同一种形状被机械复读**  反例是东方源文件, 2 种图形重复 5929 次, 最高频占比 0.85. 判据因此改成只看最高频占比

## 三条门禁判据与实测基准

| 编号 | 判据 | 门限 | 本轮原型实测 | 东方源文件实测 |
|---|---|---|---|---|
| G-A | **最高频占比** (种类数仅作提示) | <= 0.50 | 22 种 / 0.09 PASS | 6 种 / 0.85 FAIL |
| G-B | 静止事件占比 | <= 0.15 | 0.000 PASS | 0.001 PASS |
| G-C | 整行内按字序点亮时刻严格递增且首末不越界 | 无例外 | 23 组全过 PASS | 22 组里 21 组顺序非递增 FAIL |

G-C 的含义: 首字点亮不晚于行时长的 25%, 末字不晚于 95%. 实测原型第一版就栽在这里  小组 (2 到 3 字) 末字点亮到 97%, 长句末字到 98%, 门禁直接报出 3 个越界. 修法是把整组点亮压缩到行时长的 88% 以内, 留出尾部"全亮"时间

## 归一化的对照数字 (写进交付说明)

同一份内容, 两种裁剪方式的实测对比 (窗口 500x350)

- 动态裁剪: 缩放系数 0.4912 到 0.8460, 相邻帧跳变最大 0.3436, 相对漂移 56.6%
- 归一化裁剪: 缩放系数恒为 0.4329, 跳变恒为 0

**归一化的常量比动态裁剪的中位小 30.9%, 这是正常的**  它用恒定换掉了漂移

## 一次外部 forward-test 找出的五个真缺陷 (已全修, 改代码时别改回去)

让一个不知情的 agent 拿着 SKILL.md 独立跑一遍, 找出的问题比自测多得多. 记在这里

1. **暗底根本没被实现**. 把暗底色写进 Style 的 BackColour 在 BorderStyle=1 下**不渲染**  实测在纯白底上渲染, 暗像素占比 0.0000%. 而对比度门禁却对着这个不存在的底板算出 17.92:1. 修法: 用 ``p1`` 单独画一个矩形事件. 修后同一实验 7.34%, 关掉暗底是 0.54%. **凡是"某个机制被断言存在"的地方, 都要有一步能证伪它. **
2. **G-A 门限与句子数耦合**. 每句只出 1 个母题时, 种类数上限就是句子数, 5 句样本必然 FAIL. 修法: 门限自动按装饰组数封顶, 并打印为什么降; 短样本改看最高频占比
3. **形状指纹把渲染宽度算进种类数**. 同一个母题在宽 539 与 598.9 被算成两种, 既虚高种类数又掩盖真复读. 修法: 指纹只用段数与归一化宽高比, 绝对尺寸不进指纹
4. **语义映射的单假名误命中**. 助词「て」落在「手」的关键词里, 5 句里 3 句被判成同一种母题. 修法: 假名关键词一律 2 音节以上, 优先汉字
5. **幽灵态对比度默认不测**. 用 --ass 模式读样式时不会自动测幽灵态, 必须显式传 --ghost. readability.md 给了 3:1 门限, 但默认跑法漏掉了它

## 常见失败与定位方向

| 现象 | 先查什么 |
|---|---|
| measure_bbox 报空帧很多 | 背景色没传对; 或幽灵态对比度太低 (见 readability.md) |
| 越界但目视看不出来 | 是不是用了带 t 的位移标签, 而不是只改透明度/颜色 |
| 门禁 G-A FAIL 但母题明显不止一种 | 指纹把标签参数也算进去了 (要先剥花括号) |
| 门禁 G-C FAIL 全是"无标记" | 这一组字根本没有点亮动画, 只有静态色 |
| 渲染出来字很小 | 安全区太大, 裁剪缩放被高度那一维压住 (见 normalization.md) |
| 第二遍收紧后出现 1 到 4 像素的越界 | 安全区没留内缩余量. 描边/阴影/字形 overshoot 会往外顶, 留 8px |
| 矮安全区里文字顶出上边十几像素 | 字号有个"兜底下限"在硬顶. 放不下应当缩字号并告警, 不是保底 |
| 白底上渲染看不到暗底 | 暗底必须用绘图事件画, BackColour 在 BorderStyle=1 下不渲染 |
| 门禁报"种类 N"但明显有两种是同一个形状 | 指纹把绝对尺寸算进去了 (只应取段数与归一化宽高比) |
| 短样本 gradient_gate 的 G-A 永远 FAIL | 门限与句数耦合. 每句 1 母题时上限等于句数 |
| 大部分句子被判成同一种母题 | 语义映射里有单假名关键词. 日文助词会误命中 |

## 三条实测踩过的生成器缺陷 (已在代码里修掉, 改代码时别改回去)

1. **字号只按宽度自适应**. 矮安全区里文字会溢出底边  实测在安全区高 87 时溢出 3px、高 58 时溢出 4px. 修法: 字号同时受宽与高约束, 高度项用 1.77 倍字号 (文字带 1.27 加母题带 0.50)
2. **给字号设兜底下限**. 用 max 保底 18px 会在矮安全区里让文字直接顶出上边 12px. 放不下就该缩字号并告警
3. **纵向排版漏算母题带**. 文字带与母题带是叠加占高的, 不是共用. 改成[margin][余量][文字带][母题带][余量][margin] 的显式排版后, 三个不同尺寸的安全区全部零越界
